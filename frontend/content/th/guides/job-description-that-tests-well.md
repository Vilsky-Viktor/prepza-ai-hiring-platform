# วิธีเขียนรายละเอียดงานให้สร้างแบบทดสอบได้ดี

รายละเอียดงานทำหน้าที่สองอย่าง อย่างแรกคือบอกผู้สมัครว่าตำแหน่งนี้คืออะไร อย่างที่สองคือเป็นจุดเริ่มต้นของทุกสิ่งที่คุณจะตรวจในภายหลัง ทั้งการคัดกรองเรซูเม่ แบบทดสอบทักษะ และคำถามสัมภาษณ์ เมื่อรายละเอียดงานคลุมเครือ ทุกขั้นต่อจากนั้นต้องเดาว่างานนี้ต้องการอะไร และแบบทดสอบทักษะที่สร้างจากมันก็จะกลายเป็นการทดสอบสิ่งที่เดา

คู่มือนี้พูดถึงหน้าที่อย่างที่สอง คือการเขียนรายละเอียดงานที่นำไปสร้างแบบทดสอบทักษะได้ เหมาะสำหรับ hiring manager และ recruiter ไม่ว่าคุณจะใช้เครื่องมือใด นิสัยการเขียนแบบเดียวกันนี้ยังทำให้ประกาศรับสมัครงานชัดเจนขึ้นด้วย

## ทำไมรายละเอียดงานจึงเป็นตัวกำหนดแบบทดสอบ

แบบทดสอบความรู้มีประโยชน์เมื่อทดสอบสิ่งที่งานต้องการจริง ๆ งานวิจัยด้านการจ้างงานจัดให้แบบทดสอบความรู้ในงานเป็นหนึ่งในวิธีที่ทำนายผลการทำงานได้ดีกว่าโดยเฉลี่ย แต่ค่าประมาณนี้เป็นของแบบทดสอบที่สร้างขึ้นสำหรับงานนั้นโดยเฉพาะ แบบทดสอบความรู้ที่ไม่เกี่ยวกับงานทำนายได้น้อยกว่า (ดู [แบบทดสอบทักษะ เทียบกับการคัดกรองเรซูเม่](/guides/skills-tests-vs-cv-screening))

กฎการจ้างงานของสหรัฐฯ ก็พูดเรื่องเดียวกันในแง่กฎหมาย แนวปฏิบัติร่วมว่าด้วยกระบวนการคัดเลือกพนักงาน (Uniform Guidelines on Employee Selection Procedures) คาดหวังให้แบบทดสอบที่อาศัยความตรงเชิงเนื้อหาตั้งอยู่บนการวิเคราะห์งาน ซึ่งเน้นที่ "พฤติกรรมในการทำงานและงานที่เกี่ยวข้องกับพฤติกรรมนั้น" ([29 CFR 1607.14(C)](https://www.law.cornell.edu/cfr/text/29/1607.14)) ในทางปฏิบัติ สำหรับทีมส่วนใหญ่ รายละเอียดงานก็คือการวิเคราะห์นั้นที่เขียนเป็นลายลักษณ์อักษร และภายใต้กฎหมายคนพิการแห่งสหรัฐฯ (ADA) รายละเอียดงานที่เขียนไว้ก่อนลงประกาศหรือสัมภาษณ์ถือเป็นหลักฐานของหน้าที่หลักของงานนั้น ([42 U.S.C. 12111(8)](https://www.law.cornell.edu/uscode/text/42/12111))

ดังนั้นรายละเอียดงานจึงคุ้มค่าที่จะใช้เวลาเพิ่มอีกครึ่งชั่วโมง ไม่ว่ามันเขียนอะไรไว้ แบบทดสอบก็จะถามเรื่องนั้น

## รายละเอียดงานที่ดีให้อะไรกับแบบทดสอบ

### 1. ทักษะ เครื่องมือ และแนวคิดที่ชัดเจน

ระบุสิ่งที่คนต้องรู้เพื่อทำงานนี้ ด้วยถ้อยคำที่แบบทดสอบนำไปถามได้

| ทดสอบได้ยาก | ทดสอบได้ |
| --- | --- |
| มีพื้นฐานด้านการเงินแน่น | กระทบยอดบัญชีธนาคาร เข้าใจกฎภาษีมูลค่าเพิ่ม บันทึกรายการบัญชีในบัญชีแยกประเภททั่วไป |
| มีกรอบคิดแบบใช้ข้อมูลขับเคลื่อน | เขียน SQL query ที่มี join และ aggregation สร้างแดชบอร์ดใน Power BI |
| มีทักษะบริการลูกค้ายอดเยี่ยม | จัดการการคืนเงินและข้อร้องเรียนตามนโยบาย ใช้ macro และกฎการส่งต่อเรื่อง (escalation) ใน Zendesk |
| พัฒนาเว็บสมัยใหม่ | สร้าง React component ด้วย hooks เรียกใช้ REST API เขียน unit test ด้วย Jest |

ระบุชื่อเครื่องมือหรือมาตรฐานจริงเมื่อมันสำคัญ "โปรแกรมบัญชี" ทำให้แบบทดสอบต้องเลือกเอง แต่ "Xero" ไม่ต้อง หากเครื่องมือหลายตัวใช้แทนกันได้ ให้เขียนตรง ๆ ("ฐานข้อมูลเชิงสัมพันธ์ เช่น PostgreSQL") และคาดว่าแบบทดสอบจะครอบคลุมประเภทของเครื่องมือ ไม่ใช่ทุกชื่อในรายการ

### 2. ระดับ

หัวข้อเดียวกันทดสอบได้ในความลึกที่ต่างกันมาก นักวิเคราะห์ระดับจูเนียร์ควรรู้ว่า join ทำอะไร ส่วนระดับซีเนียร์ควรรู้ว่าทำไม query ถึงช้าและควรแก้อะไร บอกให้ชัดว่าคุณต้องการแบบไหน:

- **ขอบเขต:** อะไรที่เขาตัดสินใจเองได้ และอะไรที่ส่งต่อให้คนอื่น
- **ความซับซ้อน:** กรณีทั่วไป หรือกรณีที่ไม่ปกติและการชั่งน้ำหนักข้อดีข้อเสีย
- **ระดับตำแหน่ง:** จูเนียร์ กลาง หรือซีเนียร์ ในชื่อตำแหน่งหรือในเนื้อหา

จำนวนปีประสบการณ์เป็นตัวแทนของระดับแบบคร่าว ๆ และเป็นตัวแทนที่อ่อน ในงานวิจัยข้างต้น มันเป็นหนึ่งในตัวทำนายผลการทำงานที่อ่อนที่สุด หากคุณใส่ไว้ ให้อธิบายงานที่จำนวนปีเหล่านั้นควรเตรียมคนให้พร้อมด้วย

### 3. สิ่งที่คนในตำแหน่งนี้ทำในแต่ละวัน

หน้าที่ความรับผิดชอบคือบรรทัดที่มีประโยชน์ที่สุดสำหรับแบบทดสอบ "จัดทำแบบยื่นภาษีมูลค่าเพิ่มรายเดือน" หรือ "คัดแยกบั๊กที่เข้ามาและทำให้เกิดซ้ำ" บอกผู้เขียนข้อสอบว่าใช้ความรู้อะไรและในสถานการณ์ใด เขียนหน้าที่เป็นคำกริยากับกรรม แบบเดียวกับที่คุณอธิบายงานให้เพื่อนร่วมงานใหม่ฟัง

หากไม่แน่ใจว่าตำแหน่งหนึ่งมักทำอะไร [O*NET OnLine](https://www.onetonline.org/) มีรายการงานทั่วไป เทคโนโลยี และความรู้ของอาชีพหลายร้อยอาชีพ ใช้เป็นเช็กลิสต์ แล้วเก็บไว้เฉพาะสิ่งที่ตำแหน่งของคุณทำจริง

### 4. แยกคุณสมบัติที่ต้องมีกับคุณสมบัติที่มีก็ดีให้ชัด

แบบทดสอบที่ตรวจคุณสมบัติที่มีก็ดีจะคัดคนออกเพราะเรื่องที่คุณสอนได้ภายในเดือนเดียว ตัดสินใจว่าทักษะใดที่คนต้องมีตั้งแต่วันแรก แล้วทำเครื่องหมายส่วนที่เหลือให้ชัด หรือเอาออกจากข้อความที่ใช้สร้างแบบทดสอบ

ความรู้ที่ทีมของคุณตั้งใจจะสอนระหว่างทำงานไม่ควรอยู่ในแบบทดสอบคัดกรองเลย แนวปฏิบัติร่วมระบุว่าแบบทดสอบที่อาศัยความตรงเชิงเนื้อหาไม่เหมาะกับความรู้ "ที่คาดว่าพนักงานจะได้เรียนรู้ระหว่างทำงาน" ([29 CFR 1607.14(C)(1)](https://www.law.cornell.edu/cfr/text/29/1607.14))

## สิ่งที่ควรตัดออก

บางบรรทัดช่วยประกาศรับสมัครงานแต่ไม่ช่วยอะไรแบบทดสอบเลย บางบรรทัดไม่ควรอยู่ตรงนั้นตั้งแต่แรก

- **คำที่บอกบุคลิกและทัศนคติ:** "กระตือรือร้น ทำงานเชิงรุก" "ตัวท็อป" "มี passion" ตรวจด้วยคำถามวัดความรู้ไม่ได้ และมักอ่านเหมือนบรรยายประเภทของคน มากกว่าบรรยายงาน
- **วัฒนธรรมองค์กร สวัสดิการ และสโลแกน** เก็บไว้ในประกาศได้ถ้าต้องการ แต่ไม่ใช่เนื้อหาสำหรับแบบทดสอบ
- **คุณสมบัติบังคับ:** ใบอนุญาต สิทธิในการทำงาน ภาษา ช่วงเวลาที่ทำงานได้ เป็นการตรวจแบบใช่หรือไม่ในขั้นคัดกรองเรซูเม่ ไม่ใช่ความรู้ที่ต้องทดสอบ
- **ถ้อยคำที่ทำให้คนบางกลุ่มไม่กล้าสมัคร** EEOC (คณะกรรมการโอกาสการจ้างงานที่เท่าเทียม) ของสหรัฐฯ ยกตัวอย่างประกาศที่ต้องการ "ผู้หญิง" หรือ "ผู้ที่เพิ่งจบการศึกษา" ซึ่ง "อาจทำให้ผู้ชายและคนอายุเกิน 40 ปีไม่กล้าสมัคร" และอาจผิดกฎหมาย ([EEOC](https://www.eeoc.gov/prohibited-employment-policiespractices)) ใน EU และสหราชอาณาจักรก็มีกฎคล้ายกัน บรรยายงาน ไม่ใช่คนที่คุณนึกภาพว่าจะมาทำงานนี้
- **ทุกอย่างที่บริษัททำ** ย่อหน้าเกี่ยวกับผลิตภัณฑ์ที่ตำแหน่งนี้ไม่เคยแตะอาจกลายเป็นหัวข้อหนึ่งในแบบทดสอบ

## ประกาศที่เผยแพร่กับข้อความที่ใช้สร้างแบบทดสอบไม่จำเป็นต้องเหมือนกัน

ประกาศต้องขายตำแหน่งงาน ส่วนแบบทดสอบต้องการแค่คุณสมบัติ ถ้าประกาศของคุณยาว ไม่จำเป็นต้องสร้างแบบทดสอบจากทั้งหมด วางคุณสมบัติและหน้าที่ พร้อมหนึ่งบรรทัดที่บอกระดับ แล้วตัดที่เหลือออก แบบทดสอบที่สร้างจาก 15 บรรทัดที่แม่นยำมักดีกว่าแบบที่สร้างจากสามหน้า

## ตัวอย่าง

**ก่อน:**

> เรากำลังมองหานักวิเคราะห์ข้อมูลตัวท็อป ประสบการณ์ 5 ปีขึ้นไป และหลงใหลในข้อมูล คุณจะได้ทำงานกับทีมสุดเจ๋งของเราในโปรเจกต์ที่น่าตื่นเต้นด้วยเครื่องมือทันสมัย (SQL, Python, เครื่องมือ BI ฯลฯ) ต้องมีทักษะการสื่อสารยอดเยี่ยมและ growth mindset มีอาหารกลางวันฟรี และออฟฟิศพาน้องหมามาได้!

แบบทดสอบที่สร้างจากข้อความนี้ต้องเดาระดับ เดาว่า SQL แบบไหน เครื่องมือ BI ตัวใด และ "โปรเจกต์ที่น่าตื่นเต้น" ทำอะไรบ้าง ข้อความครึ่งหนึ่งทดสอบไม่ได้

**หลัง:**

> **นักวิเคราะห์ข้อมูล (ระดับกลาง)** ทำงานวิเคราะห์ประจำได้เอง และทำงานร่วมกับนักวิเคราะห์อาวุโสในการสร้างโมเดลใหม่
>
> - เขียน SQL ใน PostgreSQL: join, aggregation, window function, query plan สำหรับ query ที่ช้า
> - สร้างและดูแลแดชบอร์ด Power BI ให้ทีมขาย
> - ทำความสะอาดและรวมข้อมูลด้วย Python และ pandas
> - กำหนดและตรวจสอบตัวชี้วัด: conversion, retention, cohort analysis
> - นำเสนอผลการวิเคราะห์ให้ผู้จัดการที่ไม่ใช่สายเทคนิค ทั้งเป็นลายลักษณ์อักษรและในการประชุมสั้น ๆ
>
> มีก็ดี ไม่ทดสอบ: dbt, ประสบการณ์ในธุรกิจอีคอมเมิร์ซ

ทุกบรรทัดระบุสิ่งที่คำถามนำไปถามได้ บอกระดับไว้ และทำเครื่องหมายคุณสมบัติที่มีก็ดีไว้แล้ว

## เช็กลิสต์ก่อนสร้างแบบทดสอบ

- ทักษะแต่ละข้อระบุเครื่องมือ วิธีการ หรือแนวคิด ไม่ใช่ลักษณะนิสัย
- บอกระดับไว้: ระดับตำแหน่ง สิ่งที่ตัดสินใจเองได้ ความซับซ้อนของกรณี
- เขียนหน้าที่เป็นคำกริยากับกรรม
- แยกคุณสมบัติที่ต้องมีกับที่มีก็ดีไว้ชัดเจน
- ไม่มีสิ่งที่คุณตั้งใจจะสอนระหว่างทำงาน
- คุณสมบัติบังคับเก็บไว้สำหรับการคัดกรองเรซูเม่
- ไม่มีถ้อยคำเกี่ยวกับคนที่คุณนึกภาพไว้ มีแต่เรื่องงาน

## testee ใช้รายละเอียดงานอย่างไร

testee เป็นตัวอย่างหนึ่งของเครื่องมือที่สร้างแบบทดสอบทักษะแบบปรนัยจับเวลาจากรายละเอียดงาน นี่คือสิ่งที่มันทำกับข้อความ เพื่อให้คุณเห็นว่าคำแนะนำข้างต้นทำงานอย่างไรในทางปฏิบัติ

- **อ่านคุณสมบัติทุกข้อ** AI ดึงทักษะ เครื่องมือ แนวคิด คุณวุฒิ และหน้าที่ประจำวันแต่ละอย่างออกมาจากทุกส่วน รวมถึงส่วนที่ระบุว่าพิจารณาเป็นพิเศษหรือมีก็ดี ข้อความเรื่องวัฒนธรรม สวัสดิการ และสโลแกนจะถูกตัดออก
- **ตัวอย่างที่ใช้แทนกันได้รวมเป็นหนึ่ง** "เครื่องมือ เช่น A, B หรือที่คล้ายกัน" จะเก็บไว้เป็นประเภทของเครื่องมือ โดยใช้ตัวที่ข้อความให้ความสำคัญ (หรือตัวที่ใช้กันแพร่หลายที่สุด) เป็นตัวอย่าง รายการที่เชื่อมด้วย "และ" ยังคงแยกกัน ดังนั้นหากคุณต้องการเครื่องมือเฉพาะตัวเดียว ให้ระบุเฉพาะตัวนั้น
- **จำนวนปีและลักษณะนิสัยถูกตัดออก** จำนวนปีประสบการณ์ ระดับตำแหน่ง แรงจูงใจ และถ้อยคำทำนองเดียวกันทดสอบไม่ได้ จึงใช้เฉพาะทักษะที่ถ้อยคำเหล่านั้นอ้างถึง
- **ระดับมาจากข้อความ** ระดับตำแหน่ง จำนวนปีประสบการณ์ และขอบเขตความรับผิดชอบที่รายละเอียดงานต้องการเป็นตัวกำหนดระดับของแบบทดสอบ คือพื้นฐาน กลาง หรือยาก ระดับกำหนดความลึกของคำถาม และเวลาเริ่มต้นต่อคำถาม คือ 60 วินาทีสำหรับระดับพื้นฐานหรือกลาง และ 75 วินาทีสำหรับระดับยาก (ดู [วิธีกำหนดเวลาแบบทดสอบทักษะ](/guides/skills-test-timing-and-extra-time))
- **คุณอนุมัติหัวข้อก่อนที่จะมีการเขียนคำถามใด ๆ** คุณสมบัติจะกลายเป็นหัวข้อได้สูงสุด 10 หัวข้อ แต่ละหัวข้อมีหัวข้อย่อยได้สูงสุด 5 หัวข้อ คุณเอาเครื่องหมายถูกออกจากหัวข้อ เปลี่ยนชื่อ แก้ไขหัวข้อย่อย หรือบอกการเปลี่ยนแปลงเป็นภาษาธรรมดาได้ ("ตัด dbt ออก") คุณสมบัติที่มีก็ดีที่หลุดเข้ามาก็เอาออกได้ง่าย ๆ ตรงนี้
- **จากนั้นแต่ละหัวข้อจะมีคลังคำถามของตัวเอง** และผู้สมัครแต่ละคนจะได้ชุดคำถามแบบสุ่มจากคลังนั้น

คุณวางข้อความได้สูงสุด 10,000 ตัวอักษร หรือจะแค่อธิบายตำแหน่งในหนึ่งหรือสองบรรทัดก็ได้ ข้อความที่ไม่มีอะไรให้ทดสอบเลย เช่น สูตรอาหารหรือบทสนทนาทั่วไป จะถูกปฏิเสธ รายการทักษะสั้น ๆ ก็ใช้ได้ แต่รายละเอียดงานที่บอกระดับและงานประจำวันจะให้หัวข้อที่ดีกว่า

หากต้องการลอง วางรายละเอียดงานที่หน้าแรก หรือเริ่มจากแบบทดสอบสำเร็จรูปใน[แบบทดสอบทักษะตามตำแหน่ง](/tests)
