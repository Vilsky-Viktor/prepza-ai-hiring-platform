# วิธีเชื่อมต่อแบบทดสอบทักษะกับ ATS

ทีมสรรหาส่วนใหญ่เก็บข้อมูลผู้สมัครไว้ในระบบติดตามผู้สมัคร (ATS) แต่ใช้อีกเครื่องมือหนึ่งทำแบบทดสอบทักษะ ถ้าสองระบบนี้ไม่ได้เชื่อมกัน ก็ต้องมีคนคัดลอกอีเมลออกจาก ATS ส่งคำเชิญเอง รอ แล้วคัดลอกคะแนนกลับไป วิธีนี้ใช้ได้เมื่อมีผู้สมัคร 5 คน แต่พอถึง 50 คน คำเชิญจะส่งช้า ผลลัพธ์ค้างอยู่ในอีกแท็บที่ไม่มีใครเปิด และผู้สมัครที่ดีก็รับข้อเสนองานที่อื่นไปในระหว่างที่รอ

คู่มือนี้อธิบายว่าการเชื่อมต่อที่ดีระหว่าง ATS กับเครื่องมือทดสอบทำอะไรได้บ้าง ควรตรวจอะไรก่อนจะพึ่งพามัน และจะตั้งค่าอย่างไรให้ระบบอัตโนมัติรับงานจุกจิกไป ขณะที่คนยังเป็นผู้ตัดสินใจเรื่องการจ้างทุกครั้ง

## ทำไมต้องเชื่อมต่อ

| ไม่มีการเชื่อมต่อ | มีการเชื่อมต่อ |
| --- | --- |
| มีคนส่งออกหรือคัดลอกอีเมลของผู้สมัคร | การย้ายผู้สมัครไปยังขั้นตอนหนึ่งจะส่งคำเชิญทันที |
| คำเชิญถูกส่งเมื่อมีคนว่าง | คำเชิญถูกส่งภายในไม่กี่นาทีหลังการย้าย |
| ผลลัพธ์อยู่ในเครื่องมือทดสอบ | ผลลัพธ์แสดงที่ข้อมูลผู้สมัครใน ATS |
| ผู้จัดการฝ่ายที่รับคนถามว่า "มีใครทดสอบคนนี้หรือยัง" | ATS แสดงว่าใครทำแบบทดสอบแล้วและได้ผลอย่างไร |
| พิมพ์อีเมลผิดและตกหล่นผู้สมัคร | ATS เป็นรายชื่อเดียวของทุกคนที่สมัคร |

ความเร็วสำคัญกว่าที่เห็น ยิ่งช่วงเวลาระหว่างการสมัครกับการได้รับการติดต่อกลับนานเท่าไร ผู้สมัครก็ยิ่งถอนตัวหรือไปรับงานอื่นมากขึ้นเท่านั้น อัตราการหลุดที่แน่นอนแตกต่างกันมากตามตำแหน่งและตลาด จึงควรระวังตัวเลขที่เผยแพร่กัน แต่ทิศทางนั้นสม่ำเสมอ กระบวนการที่ช้าทำให้เสียคน และผู้สมัครที่เก่งที่สุดมักมีทางเลือกมากที่สุด

## ขั้นตอนที่ดีเป็นอย่างไร

การเชื่อมต่อที่ดีจะทำตามขั้นตอนที่คุณใช้อยู่แล้ว ไม่ได้สร้างกระบวนการใหม่ขึ้นมา

1. **ผู้สมัครยื่นใบสมัคร** และเข้ามาอยู่ใน ATS ตามปกติ
2. **คนในทีมย้ายผู้สมัครไปยังขั้นตอนทดสอบ** เช่น "แบบทดสอบทักษะ" การย้ายนี้เป็นตัวกระตุ้น คนจึงยังเป็นผู้ตัดสินว่าใครจะได้ทำแบบทดสอบ
3. **เครื่องมือทดสอบส่งคำเชิญ** โดยอัตโนมัติ สำหรับแบบทดสอบที่ผูกกับตำแหน่งงานนั้น
4. **ผู้สมัครทำแบบทดสอบ** ในเวลาที่สะดวก ภายในกำหนดเวลาที่คุณตั้งไว้
5. **ผลลัพธ์ถูกบันทึกกลับไปที่ผู้สมัครใน ATS:** คะแนน ผ่านหรือไม่ สัญญาณเตือนด้านความซื่อตรง และลิงก์ไปยังคำตอบทั้งหมด
6. **คนในทีมตรวจผลลัพธ์** แล้วตัดสินว่าจะให้ผู้สมัครไปต่อหรือไม่

มีสองเรื่องที่ตั้งใจให้ทำด้วยมือ คือการเลือกว่าใครจะได้ทำแบบทดสอบ และการตัดสินว่าจะทำอะไรต่อ การเชื่อมต่อเพียงตัดงานคัดลอกที่อยู่ตรงกลางออกไป

### ทำไมไม่ส่งทุกครั้งที่มีใบสมัครใหม่

บางเครื่องมือเชิญทุกคนที่สมัคร ซึ่งอาจใช้ได้กับตำแหน่งที่รับคนจำนวนมากที่ผู้สมัครทุกคนทำแบบทดสอบเดียวกัน แต่ขั้นตอนที่คุณย้ายผู้สมัครเข้าไปเองนั้นควบคุมได้ง่ายกว่า คุณข้ามผู้สมัครที่ไม่ผ่านคุณสมบัติบังคับอย่างชัดเจนได้ (ไม่มีใบอนุญาตทำงาน อยู่ผิดพื้นที่) และไม่ต้องทดสอบหรือจ่ายเงินให้กับคนที่คุณจะปฏิเสธอยู่แล้ว

## สิ่งที่ควรตรวจก่อนเลือกการเชื่อมต่อ

คำว่า "เชื่อมต่อกับ ATS ของคุณได้" ไม่ได้มีความหมายเดียวกันเสมอไป ถามคำถามเหล่านี้ก่อนเชื่อมต่ออะไรก็ตาม

| คำถาม | ทำไมจึงสำคัญ | คำตอบที่ดี |
| --- | --- | --- |
| เชื่อมต่ออย่างไร | รหัสผ่านที่ใช้ร่วมกันและบัญชีที่ผู้ให้บริการถือไว้ตรวจสอบหรือเพิกถอนได้ยาก | คีย์ API หรือโทเค็นที่บริษัทของคุณสร้างเองและลบได้ทุกเมื่อ |
| คีย์ทำอะไรได้บ้าง | คีย์ที่มีสิทธิ์เต็มเป็นความเสี่ยงหากรั่วไหล | สิทธิ์น้อยที่สุดที่การเชื่อมต่อต้องใช้ โดยระบุไว้ในเอกสาร |
| อะไรเป็นตัวกระตุ้นให้ส่งคำเชิญ | คุณต้องรู้แน่ชัดว่าผู้สมัครจะได้รับอีเมลเมื่อไร | ขั้นตอนเฉพาะที่คุณเลือกเองในแต่ละตำแหน่งงาน |
| ผลลัพธ์ไปอยู่ที่ไหน | ผลลัพธ์ที่ไม่มีใครเห็นก็ไม่มีประโยชน์ | ในโปรไฟล์ผู้สมัคร เป็นบันทึกหรือความคิดเห็นที่ทีมของคุณอ่านอยู่แล้ว |
| ถ้าส่งคำเชิญไม่สำเร็จจะเกิดอะไรขึ้น | เครดิตหมด พิมพ์ผิด บัญชีถูกหยุดชั่วคราว ผู้สมัครค้างอยู่โดยไม่มีใครรู้ | มีคนได้รับแจ้ง และเชิญผู้สมัครใหม่ได้ |
| เหตุการณ์เดียวกันอาจถูกประมวลผลสองครั้งได้ไหม | ATS ส่งเหตุการณ์ซ้ำได้ ผู้สมัครไม่ควรได้รับคำเชิญสองครั้ง | ผู้สมัครแต่ละคนได้รับเชิญหนึ่งครั้งต่อแบบทดสอบ ไม่ว่าเหตุการณ์จะเข้ามากี่ครั้ง |
| ยืนยันเหตุการณ์ที่เข้ามาอย่างไร | ที่อยู่ที่ไม่มีการยืนยันอาจถูกส่งเหตุการณ์ปลอมเข้ามาได้ | คำขอที่มีลายเซ็นซึ่งเครื่องมือตรวจสอบ |
| เก็บข้อมูลผู้สมัครไว้นานเท่าไร | กฎหมายคุ้มครองข้อมูลอย่าง GDPR คาดหวังระยะเวลาการเก็บที่ชัดเจน | มีกำหนดระยะเวลาชัดเจน และลบเมื่อคุณลบตำแหน่งงาน แบบทดสอบ หรือบัญชี |
| ค่าใช้จ่ายเท่าไร | แพ็กเกจที่คิดตามจำนวนผู้ใช้อาจทำให้ระบบอัตโนมัติมีราคาแพง | ค่าใช้จ่ายที่คาดการณ์ได้ต่อผู้สมัครที่ทำแบบทดสอบ |

ถ้าผู้ให้บริการตอบคำถามเรื่องความล้มเหลวและการซ้ำซ้อนไม่ได้ชัดเจน ก็เตรียมรู้คำตอบจากปัญหาที่เกิดขึ้นจริงได้เลย

### การคุ้มครองข้อมูล

การเชื่อมต่อสองระบบหมายถึงข้อมูลผู้สมัคร อย่างน้อยคือชื่อและอีเมล จะถูกส่งไปมาระหว่างสองบริษัท ภายใต้ GDPR และกฎหมายที่คล้ายกัน ผู้ให้บริการแบบทดสอบมักเป็นผู้ประมวลผลข้อมูลของคุณ คุณจึงต้องมีข้อตกลงการประมวลผลข้อมูล และควรแจ้งผู้สมัครในประกาศความเป็นส่วนตัวหรือในคำเชิญว่าแบบทดสอบทักษะเป็นส่วนหนึ่งของกระบวนการ ส่งต่อข้อมูลเท่าที่แบบทดสอบจำเป็นต้องใช้เท่านั้น อ่านเพิ่มเติมเรื่องแง่กฎหมายของแบบทดสอบและการใช้ AI ในการจ้างงานได้ที่ [การใช้ AI ในการจ้างงานถูกกฎหมายใน EU หรือไม่?](/guides/is-ai-hiring-legal-in-the-eu)

## รายการตรวจสอบการตั้งค่า

ก่อนเปิดใช้กับตำแหน่งที่รับสมัครจริง:

1. **สร้างขั้นตอนสำหรับการทดสอบโดยเฉพาะ** ใน ATS เช่น "แบบทดสอบทักษะ" อย่าใช้ขั้นตอนที่มีความหมายอื่นซ้ำ ไม่เช่นนั้นผู้สมัครจะได้รับคำเชิญโดยไม่ตั้งใจ
2. **สร้างคีย์จากบัญชีผู้ดูแล** ที่มองเห็นทุกตำแหน่งงานที่คุณต้องการผูก และให้เฉพาะสิทธิ์ที่เอกสารระบุไว้
3. **ผูกแต่ละตำแหน่งงานกับแบบทดสอบของตำแหน่งงานนั้น** และเลือกขั้นตอนที่เป็นตัวกระตุ้นให้ส่งคำเชิญ
4. **ตั้งค่าเว็บฮุก** หาก ATS ของคุณต้องให้ตั้งค่าเอง แล้ววางรหัสลับของเว็บฮุกในช่องที่เครื่องมือขอ
5. **ทดสอบกับตัวเอง** เพิ่มผู้สมัครด้วยอีเมลของคุณเอง ย้ายไปยังขั้นตอนนั้น ทำแบบทดสอบ แล้วตรวจว่าบันทึกปรากฏใน ATS
6. **กำหนดว่าใครคอยดูความล้มเหลว** ใครจะได้รับแจ้งเมื่อส่งคำเชิญไม่ได้ และใครเป็นคนแก้ไข
7. **ตกลงกันว่าจะอ่านผลอย่างไร** เกณฑ์ผ่านเป็นแนวทาง ไม่ใช่การปฏิเสธอัตโนมัติ ตัดสินเรื่องนี้ก่อนผลจะเข้ามา ไม่ใช่หลังจากนั้น

## ข้อผิดพลาดที่พบบ่อย

- **ทำให้การตัดสินใจเป็นอัตโนมัติแทนที่จะเป็นงานเอกสาร** การปฏิเสธทุกคนที่ได้คะแนนต่ำกว่าเกณฑ์โดยอัตโนมัติ จะตัดการตรวจโดยคนที่ช่วยจับคำถามที่ไม่ดี หรือผู้สมัครที่มีปัญหาการเชื่อมต่อ ให้คะแนนเป็นตัวจัดลำดับ แล้วให้คนเป็นผู้ตัดสิน
- **ใช้ขั้นตอนผิดเป็นตัวกระตุ้น** ขั้นตอนที่รีครูตเตอร์ใช้ด้วยเหตุผลอื่นจะส่งแบบทดสอบไปให้คนที่ไม่ควรได้รับ
- **ใช้แบบทดสอบเดียวกับทุกตำแหน่ง** การเชื่อมต่อทำให้ส่งแบบทดสอบเดียวกันไปทุกที่ได้ง่าย แต่แบบทดสอบจะช่วยได้มากที่สุดเมื่อสร้างมาสำหรับตำแหน่งนั้นโดยเฉพาะ ดู [แบบทดสอบทักษะ เทียบกับการคัดกรองเรซูเม่](/guides/skills-tests-vs-cv-screening)
- **ไม่มีใครคอยดูความล้มเหลว** ถ้าคำเชิญส่งไม่สำเร็จโดยไม่มีใครรู้ ผู้สมัครจะรออีเมลที่ไม่มีวันมาถึง และคุณจะคิดว่าเขาเพิกเฉย
- **คีย์ผูกกับคนที่กำลังจะลาออก** คีย์ ATS บางแบบทำงานในนามของคนที่สร้างมัน เมื่อบัญชีของคนนั้นถูกปิด การเชื่อมต่อก็หยุดทำงาน ให้ใช้บัญชีที่จะอยู่ต่อไป และเชื่อมต่อใหม่เมื่อมีการเปลี่ยนหน้าที่
- **ลืมผู้สมัครที่อยู่นอก ATS** ผู้สมัครจากการแนะนำและผู้ที่สมัครโดยตรงซึ่งไม่เคยเข้า ATS ก็ต้องได้รับคำเชิญเช่นกัน ควรมีวิธีเชิญด้วยมือไว้ด้วย

## prepza ทำอย่างไร

prepza เชื่อมต่อกับ **Workable, Greenhouse, Teamtailor, Recruitee และ Breezy HR** โดยทำตามขั้นตอนข้างต้น

- **คีย์ของคุณ คุณควบคุมเอง** เจ้าของหรือผู้ดูแลเชื่อมต่อ ATS ในแท็บการเชื่อมต่อระบบของบริษัท ด้วยคีย์ที่บริษัทของคุณสร้างใน ATS prepza ตรวจคีย์ก่อนบันทึก เก็บแบบเข้ารหัส และจะไม่แสดงคีย์นั้นอีก การยกเลิกการเชื่อมต่อจะลบคีย์และตำแหน่งงานที่ผูกไว้ทันที
- **ผูกตำแหน่งงานกับการสัมภาษณ์** เลือกตำแหน่งงานใน ATS และขั้นตอนที่เป็นตัวกระตุ้นให้ส่งคำเชิญ แล้วผูกกับการสัมภาษณ์ที่มีอยู่ใน prepza หรือสร้างการสัมภาษณ์ใหม่จากข้อความประกาศงานใน ATS คุณตรวจหัวข้อก่อนที่จะมีการเขียนคำถามใด ๆ
- **ย้ายผู้สมัคร แล้วคำเชิญก็ถูกส่ง** ผู้สมัครแต่ละคนได้รับเชิญหนึ่งครั้งต่อการสัมภาษณ์ แม้ ATS จะส่งเหตุการณ์เดียวกันมาสองครั้ง
- **ผลลัพธ์กลับไปที่ ATS** เมื่อผู้สมัครทำเสร็จ prepza จะเพิ่มบันทึกหรือความคิดเห็นที่ผู้สมัครคนนั้นใน ATS พร้อมผลการประเมิน ผ่านหรือไม่ สัญญาณเตือนด้านความซื่อตรง (ออกจากหน้า พยายามคัดลอก เลือกคำตอบเร็วเกินกว่าจะได้อ่านคำถาม) และลิงก์ไปยังใบประเมินที่มีคำตอบทั้งหมด
- **ความล้มเหลวไม่ถูกมองข้าม** ถ้าเชิญผู้สมัครไม่ได้ เช่น เพราะบริษัทเครดิตหมด ถึงขีดจำกัดอีเมล หรือ prepza หยุดการเชิญไว้ชั่วคราว สมาชิกทุกคนของบริษัทจะได้รับการแจ้งเตือนที่ระบุชื่อ ATS ผู้สมัครที่ไม่ได้รับเชิญเพราะเครดิตไม่พอจะได้รับเชิญโดยอัตโนมัติหลังเติมเครดิต และผู้สมัครที่รออยู่ในตำแหน่งงานใดก็ได้สามารถเชิญใหม่ได้ด้วยการคลิกครั้งเดียว
- **Slack ถ้าคุณใช้** prepza โพสต์การแจ้งเตือน เช่น ผู้สมัครที่ทำเสร็จแล้ว หรือผู้สมัครจาก ATS ที่เชิญไม่ได้ ไปยังช่อง Slack ที่คุณเลือกได้
- **แพลตฟอร์มของคุณเอง** ถ้า ATS ของคุณไม่อยู่ในรายการ [API](/api-docs) ของ prepza ช่วยให้คุณเชิญผู้สมัครด้วยคีย์ API และรับเว็บฮุกที่มีลายเซ็นเมื่อผู้สมัครเริ่มทำ ทำเสร็จ คำเชิญส่งไม่ถึง คำเชิญหมดอายุ หรือผู้สมัครถูกลบออก และเมื่อการสัมภาษณ์พร้อมใช้งาน
- **เก็บข้อมูลตามระยะเวลาที่กำหนด** ผู้สมัครที่บันทึกมาจาก ATS จะถูกลบหลัง 365 วัน หรือเร็วกว่านั้นพร้อมกับการสัมภาษณ์หรือบริษัท

ATS บางระบบต้องทำขั้นตอนหนึ่งในฝั่งของระบบนั้น Greenhouse, Teamtailor และ Recruitee ให้คุณเพิ่มเว็บฮุกเอง หน้าต่างคำแนะนำของ prepza จะแสดงที่อยู่และตำแหน่งที่ต้องวางรหัสลับ ส่วนเว็บฮุกของ Workable และ Breezy HR นั้น prepza ตั้งค่าให้เอง

คิดราคาต่อผู้สมัคร ไม่มีการสมัครสมาชิก คุณจ่ายเฉพาะผู้สมัครที่ตอบอย่างน้อยหนึ่งคำถาม: คนละ $5 เมื่อเติมเครดิต $50, $4 เมื่อเติมตั้งแต่ $200, $3 เมื่อเติมตั้งแต่ $600 และ $2 เมื่อเติมตั้งแต่ $1,000 ราคาในที่นี้เป็นดอลลาร์สหรัฐ และเป็นสกุลเงินท้องถิ่นในแคนาดา ออสเตรเลีย อิสราเอล โปแลนด์ สวิตเซอร์แลนด์ ญี่ปุ่น เกาหลีใต้ ไต้หวัน ฮ่องกง ประเทศไทย สิงคโปร์ อินเดีย ยุโรปส่วนอื่นๆ และสหราชอาณาจักร VAT หรือภาษีขายจัดการตอนชำระเงิน การเชื่อมต่อ ATS และการสร้างการสัมภาษณ์ฟรี และผู้สมัคร 3 คนแรกของบริษัทแรกของคุณฟรี ดู [ราคา](/pricing)
