# Paano sumulat ng job description na madaling gawan ng test

Dalawa ang trabaho ng isang job description. Sinasabi nito sa mga aplikante kung ano ang role, at ito ang panimulang punto ng lahat ng susuriin mo pagkatapos: ang CV screening, ang skills test, ang mga tanong sa interview. Kapag malabo ang job description, kailangang hulaan ng bawat susunod na hakbang kung ano ang kailangan ng trabaho, at ang skills test na gagawin mula rito ay mauuwi sa pag-test sa hula.

Tungkol ang gabay na ito sa ikalawang trabaho: ang pagsulat ng job description na puwedeng gawan ng skills test. Para ito sa mga hiring manager at recruiter, anuman ang tool na gamit mo. Ang parehong mga gawi ay nagpapalinaw rin sa job ad.

## Bakit ang job description ang nagpapasya sa test

Kapaki-pakinabang ang knowledge test kapag tine-test nito ang talagang kailangan ng trabaho. Sa hiring research, kabilang ang job knowledge tests sa mas mahuhusay na predictor ng job performance sa karaniwan, pero para sa mga test na ginawa para mismo sa trabahong iyon ang tantiyang ito; mas mahina ang prediksyon ng mga knowledge test na walang kinalaman sa trabaho (tingnan ang [Skills tests vs CV screening](/guides/skills-tests-vs-cv-screening)).

Ganoon din ang sinasabi ng mga patakaran sa empleyo sa US mula sa legal na panig. Inaasahan ng Uniform Guidelines on Employee Selection Procedures na ang test na sinusuportahan ng content nito ay nakabatay sa isang job analysis, na nakatuon sa "mga work behavior at ang mga task na kaugnay ng mga ito" ([29 CFR 1607.14(C)](https://www.law.cornell.edu/cfr/text/29/1607.14)). Sa praktika, para sa karamihan ng team, ang job description ang analysis na iyon na nakasulat. At sa ilalim ng Americans with Disabilities Act, ang nakasulat na job description na inihanda bago mag-advertise o mag-interview ay itinuturing na ebidensya ng mga essential function ng trabaho ([42 U.S.C. 12111(8)](https://www.law.cornell.edu/uscode/text/42/12111)).

Kaya sulit ang dagdag na kalahating oras sa job description. Anuman ang nakasulat dito, iyon ang itatanong ng test.

## Ang ibinibigay ng magandang job description sa test

### 1. Kongkretong skills, tools at concepts

Pangalanan ang mga dapat alam ng tao para magawa ang trabaho, sa mga salitang puwedeng itanong sa test.

| Mahirap i-test | Puwedeng i-test |
| --- | --- |
| Malakas na background sa finance | Nagre-reconcile ng bank statements, alam ang mga patakaran sa VAT, nagpo-post ng journal entries sa general ledger |
| Data-driven mindset | Sumusulat ng SQL queries na may joins at aggregations; gumagawa ng dashboards sa Power BI |
| Mahusay sa customer service | Humahawak ng refunds at complaints ayon sa policy; gumagamit ng Zendesk macros at escalation rules |
| Modern web development | Gumagawa ng React components gamit ang hooks; tumatawag ng REST APIs; sumusulat ng unit tests gamit ang Jest |

Pangalanan ang mismong tool o standard kapag mahalaga ito. Ang "accounting software" ay nag-iiwan sa test na pumili ng isa; ang "Xero" ay hindi. Kapag puwede ang alinman sa ilang tool, sabihin ito nang diretso ("isang relational database gaya ng PostgreSQL"), at asahang ang uri ng tool ang sasaklawin ng test, hindi ang bawat pangalan sa listahan.

### 2. Ang level

Puwedeng i-test ang parehong topic sa magkakaibang lalim. Dapat alam ng isang junior analyst kung ano ang ginagawa ng join; dapat alam ng isang senior kung bakit mabagal ang isang query at ano ang babaguhin. Sabihin kung alin ang kailangan mo:

- **Saklaw:** ano ang siya lang ang nagpapasya, at ano ang ipinapasa niya sa iba.
- **Complexity:** mga karaniwang kaso, o mga hindi pangkaraniwan at mga trade-off.
- **Seniority:** junior, mid-level o senior, sa job title o sa teksto.

Magaspang na pamalit sa level ang taon ng karanasan, at mahina pa: sa research sa itaas, kabilang ito sa pinakamahihinang predictor ng performance. Kung isasama mo ito, ilarawan din ang trabahong dapat naihanda ng mga taong iyon.

### 3. Ang ginagawa ng tao araw-araw

Ang mga duty ang pinakakapaki-pakinabang na linya para sa test. Ang "Inihahanda ang buwanang VAT return" o "Tina-triage ang mga pumapasok na bug at nire-reproduce ang mga ito" ay nagsasabi sa gumagawa ng test kung aling kaalaman ang ginagamit at sa anong sitwasyon. Isulat ang mga duty bilang verb at object, gaya ng paglalarawan mo ng trabaho sa isang bagong katrabaho.

Kung hindi ka sigurado kung ano ang karaniwang ginagawa ng isang role, nakalista sa [O*NET OnLine](https://www.onetonline.org/) ang mga karaniwang task, technology at kaalaman para sa daan-daang trabaho. Gamitin ito bilang checklist, saka itira lang ang talagang ginagawa ng role mo.

### 4. Malinaw na hati sa pagitan ng must-have at nice to have

Ang test na nagche-check ng nice-to-haves ay nagtatanggal ng mga tao dahil sa mga bagay na kaya mong ituro sa loob ng isang buwan. Pagpasyahan kung aling skills ang kailangan ng tao sa unang araw, at malinaw na markahan ang iba o alisin ang mga ito sa tekstong gagawan ng test.

Ang kaalamang balak ituro ng team mo habang nasa trabaho ay hindi dapat kasama sa screening test. Sinasabi ng Uniform Guidelines na hindi angkop ang test na sinusuportahan ng content nito para sa kaalamang "inaasahang matututunan ng empleyado habang nasa trabaho" ([29 CFR 1607.14(C)(1)](https://www.law.cornell.edu/cfr/text/29/1607.14)).

## Ang dapat iwanan

May mga linyang nakakatulong sa ad pero walang silbi sa test. May iba namang hindi dapat nandoon sa simula pa lang.

- **Mga salita tungkol sa personalidad at ugali:** "self-starter", "rockstar", "passionate". Hindi ito masusuri ng isang knowledge question, at madalas itong mabasa bilang isang uri ng tao sa halip na isang trabaho.
- **Culture, perks at slogans.** Itira sa ad kung gusto mo; hindi sila materyal para sa test.
- **Mahigpit na requirement:** lisensya, karapatang magtrabaho, wika, availability. Mga oo-o-hindi na check ang mga ito para sa CV screening, hindi kaalamang ite-test.
- **Mga salitang nagpapaatras sa ilang grupo ng tao.** Binibigay ng US EEOC ang halimbawa ng ad na naghahanap ng "babae" o "fresh graduate", na "maaaring magpaatras sa mga lalaki at sa mga taong lampas 40 na mag-apply" at maaaring labag sa batas ([EEOC](https://www.eeoc.gov/prohibited-employment-policiespractices)). May mga katulad na patakaran sa EU at UK. Ilarawan ang trabaho, hindi ang taong iniisip mong gagawa nito.
- **Lahat ng ginagawa ng kumpanya.** Ang isang talata tungkol sa produktong hindi kailanman hahawakan ng role ay puwedeng mauwi bilang isang topic.

## Puwedeng magkaiba ang public ad at ang tekstong gagawan ng test

Kailangang ibenta ng ad ang role; ang test ay mga requirement lang ang kailangan. Kung mahaba ang ad mo, hindi mo kailangang gawan ng test ang lahat ng ito. I-paste ang mga requirement at duty, kasama ang isang linya tungkol sa level, at iwanan ang iba. Kadalasang mas maganda ang test na gawa sa 15 tiyak na linya kaysa sa gawa sa tatlong pahina.

## Isang halimbawa

**Bago:**

> We're hiring a rockstar Data Analyst na may 5+ years of experience at passion for data! Makakatrabaho mo ang aming amazing team sa mga exciting na project gamit ang modern tools (SQL, Python, BI tools, atbp.). Must have ang great communication skills at growth mindset. May free lunch at dog-friendly office!

Kailangang hulaan ng test na gagawin mula rito ang level, aling SQL, aling BI tool, at ano ang kasama sa "exciting na project". Kalahati ng teksto ay hindi ma-te-test.

**Pagkatapos:**

> **Data Analyst (mid-level).** Mag-isang gumagawa ng mga regular na analysis, at kasama ng isang senior analyst sa mga bagong model.
>
> - Sumusulat ng SQL sa PostgreSQL: joins, aggregations, window functions, query plans para sa mabagal na queries
> - Gumagawa at nagme-maintain ng Power BI dashboards para sa sales team
> - Naglilinis at nagjo-join ng data sa Python gamit ang pandas
> - Nagde-define at nagche-check ng metrics: conversion, retention, cohort analysis
> - Nagpe-present ng findings sa mga non-technical na manager, nakasulat at sa maiikling meeting
>
> Nice to have, hindi ite-test: dbt, karanasan sa e-commerce.

Bawat linya ay nagpapangalan ng bagay na puwedeng itanong, nakasaad ang level, at may marka ang nice-to-haves.

## Checklist bago gumawa ng test

- Bawat skill ay nagpapangalan ng tool, method o concept, hindi ng ugali.
- Nakasaad ang level: seniority, ano ang siya lang ang nagpapasya, gaano ka-complex ang mga kaso.
- Nakasulat ang mga duty bilang verb at object.
- Malinaw na hiwalay ang must-haves at nice-to-haves.
- Walang anumang balak mong ituro habang nasa trabaho.
- Iniwan para sa CV screening ang mahigpit na requirement.
- Walang salita tungkol sa taong iniisip mo, tungkol lang sa trabaho.

## Paano ginagamit ng prepza ang job description

Isang halimbawa ang prepza ng tool na gumagawa ng timed multiple-choice na skills test mula sa job description. Ito ang ginagawa nito sa teksto, para makita mo kung paano gumagana ang payo sa itaas:

- **Binabasa nito ang bawat requirement.** Pinipili ng AI ang bawat skill, tool, concept, qualification at araw-araw na duty, mula sa bawat section, kasama ang mga may markang preferred o nice to have. Tinatanggal ang mga pahayag tungkol sa culture, perks at slogans.
- **Nagiging isa ang mga halimbawang puwedeng ipagpalit.** Ang "tools gaya ng A, B o katulad" ay itinatabi bilang uri ng tool, na ang tool na mas gusto ng teksto (o ang pinakalaganap) ang halimbawa. Nananatiling hiwalay ang mga item na pinagdugtong ng "at". Kaya kung isang partikular na tool ang kailangan mo, iyon lang ang pangalanan.
- **Tinatanggal ang mga taon at ugali.** Hindi mate-test ang taon ng karanasan, seniority, motivation at mga katulad na pahayag, kaya ang skill lang na tinutukoy nila ang ginagamit.
- **Galing sa teksto ang level.** Ang seniority, taon ng karanasan at saklaw ng responsibilidad na hinihingi ng job description ang nagtatakda ng level ng test: basic, medium o hard. Ang level ang nagpapasya kung gaano kalalim ang mga tanong, at ang default na oras bawat tanong: 60 segundo para sa basic o medium, 75 para sa hard (tingnan ang [Paano itakda ang oras ng skills test](/guides/skills-test-timing-and-extra-time)).
- **Ikaw ang nag-a-approve ng mga topic bago maisulat ang kahit isang tanong.** Nagiging hanggang 10 topic ang mga requirement, na may hanggang 5 subtopic bawat isa. Puwede mong i-uncheck ang isang topic, palitan ang pangalan nito, i-edit ang mga subtopic nito, o ilarawan ang pagbabago sa simpleng salita ("alisin ang dbt"). Madaling alisin dito ang nice-to-haves na nakalusot.
- **Saka nagkakaroon ang bawat topic ng sariling question bank,** at bawat aplikante ay nakakakuha ng random na set mula rito.

Puwede kang mag-paste ng hanggang 10,000 character, o ilarawan lang ang role sa isa o dalawang linya. Tinatanggihan ang tekstong walang pinapangalanang puwedeng i-test, gaya ng recipe o kuwentuhan. Gumagana ang maikling listahan ng skills, pero mas magagandang topic ang ibinibigay ng job description na may level at araw-araw na trabaho.
