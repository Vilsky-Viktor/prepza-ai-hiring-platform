# AI 智能体、MCP 和 API：是什么，以及如何用于招聘

大多数人最早接触 AI，是通过一个聊天窗口：你提问，它回答。AI 智能体更进一步。它可以在你的工具里查找信息，并在你要求时直接在工具里办事：创建一场面试、邀请一批候选人、告诉你上周谁的分数最高。Model Context Protocol（MCP，模型上下文协议）是一项标准，让你已经在用的 AI 聊天（例如 Claude 或 ChatGPT）能够连接这类工具。而 API 是软件与软件之间更早、更精确的对话方式，中间没有 AI。

本指南用通俗的语言解释这三者，说明它们在招聘中有什么用、需要注意什么，以及如何在 prepza 中使用它们。

## 什么是 AI 智能体

聊天机器人只会写文字。智能体则是带有**工具**的语言模型：工具是它可以调用的、定义明确的小操作，例如“列出这场面试的候选人”或“邀请这个邮箱”。当你提问时，智能体会决定使用哪些工具，读取工具返回的结果，并据此回答，而不是凭记忆回答。

| 聊天机器人 | AI 智能体 |
| --- | --- |
| 根据训练时学到的内容回答 | 根据通过工具读取的实时数据回答 |
| 只能描述怎么做 | 在你要求并允许时，可以直接去做 |
| 不知道时会猜 | 会去查，或者说明做不到 |
| 只存在于一个窗口里 | 在你连接的工具里工作 |

工具让智能体变得有用，也决定了它是否安全。好的智能体只能使用给它的工具，只能在你的权限范围内行事，并且只做你要求的事。

## 什么是 MCP

Model Context Protocol 是 Anthropic 于 2024 年底推出的开放标准，如今 Claude、ChatGPT 以及许多其他 AI 应用和开发者工具都已支持。它常被比作 AI 的 USB-C 接口：不必让每个 AI 应用都为每个工具单独开发连接，工具只要提供一个 **MCP 服务器**，任何支持 MCP 的 AI 应用都能使用它。

MCP 服务器会告诉 AI 应用三件事：

1. **有哪些工具**，包括名称、说明以及每个工具需要的信息。
2. **哪些工具只读取数据**，哪些会做出更改，这样 AI 应用就能在更改前先征求你的同意。
3. **你是谁**，通过你一次性批准的登录来确认，因此每次调用都以你的身份、按你的权限运行。

对你来说，这意味着你可以在已经在用的聊天里操作工具，不用在窗口之间来回复制数据。

## 什么是 API，它有什么不同

API（应用程序编程接口）是一个程序可以向另一个程序发送的一组固定请求，例如“列出这场面试的候选人”“邀请这个邮箱”。由你的开发人员编写代码来发送这些请求。整个过程没有 AI 参与：同样的请求永远做同样的事，而这正是无人值守的自动化所需要的。

| | AI 智能助手（在应用内） | MCP（在 Claude 或 ChatGPT 中） | API |
| --- | --- | --- | --- |
| 谁在用 | 你，在 prepza 中 | 你，在你的 AI 聊天中 | 你的平台的代码 |
| 怎么提要求 | 用你自己的话 | 用你自己的话 | 开发人员编写的固定请求 |
| 谁批准更改 | 你，在卡片上 | 你，在你的 AI 应用中 | 你的代码，按写好的逻辑 |
| 最适合 | 快速提问和处理小任务 | 把 prepza 与你的其他工具和文件结合使用 | 无人值守也能运行的自动化 |
| 以什么身份登录 | 你本人 | 你本人 | 公司密钥 |

有人参与其中时，用智能助手或 MCP。当你自己的系统需要自动邀请候选人并收集结果时，例如从招聘官网或内部 HR 工具发起，就用 API。

## 在招聘中有什么用

招聘中有大量分散在不同工具里的重复性小步骤。AI 智能体恰好擅长处理这些：

- **关于招聘进展的问题。**“本周 Senior Backend 有哪些候选人通过了？”“谁还没开始面试？”“数据分析师岗位的平均成绩是多少？”
- **设置工作。**“根据这份职位描述创建一场面试”“把及格线设为 70%”“给这位候选人增加 50% 的时间。”
- **批量操作。**“邀请这 12 个人参加前端面试”，名单直接从邮件或表格里粘贴过来。
- **整合多种来源。** 在 Claude 或 ChatGPT 中，你可以把 prepza 与其他已连接的工具和文件结合起来：把文档里的职位描述与面试的主题进行对比，或给进入候选名单的候选人起草一封消息。

它不应该做的，是做出招聘决定。成绩用来辅助人的判断，而不是取而代之。让智能体去排序、总结和准备，决定仍由人来做。关于这一点在法律上为什么也很重要，请参阅[在欧盟用 AI 招聘合法吗？](/guides/is-ai-hiring-legal-in-the-eu)

## 需要注意什么

把 AI 连接到你的招聘数据，应当像给同事开放访问权限一样谨慎。

| 风险 | 应对方式 |
| --- | --- |
| 智能体做了你本不想做的事 | 更改需要你先批准，而且它只做你要求的事 |
| 它看到了不该看的内容 | 它以你的身份行事：你能看到什么，它就看到什么，仅此而已 |
| 数据中隐藏的指令 | 候选人的姓名、回答和文件都只是数据，绝不会被当作要执行的指令 |
| 机密信息进入聊天 | API 密钥和密码绝不经过聊天 |
| 无法挽回的错误 | 删除账号或公司只能在应用内进行，并且有单独的确认步骤 |
| 数据离开你的工具 | 数据会进入你连接的 AI 应用，并受该应用的条款约束：只连接公司允许使用的应用 |
| 使用失控 | 每小时可执行的操作数量有上限 |

在把任何 AI 应用连接到工作数据之前，请先查看公司关于 AI 工具的政策，并在隐私声明中告知候选人有哪些服务会处理他们的数据。

## 在页面之外使用 prepza 的三种方式

### 1. 内置智能助手

在任意页面的顶部选择 **问问智能助手**。智能助手了解你的公司、面试、候选人、点数和集成，也了解 prepza 是如何运作的。它会用你的语言回答，你可以打字，也可以直接说话。

- **它根据你的数据回答**，看到的范围和你一样：管理员能看到管理员能看的内容，查看者能看到查看者能看的内容。
- **它知道你在哪个页面。** 问“我在这个页面上能做什么？”就能看到该页面的指南；在某个面试的候选人页面问“这里谁最优秀？”，它会直接回答这个面试的情况，不会再问是哪一个。
- **它准备更改，由你确认。** 当你让它邀请候选人时，它会显示一张卡片，准确列出将要发生的事，例如“邀请 12 位候选人参加 Backend developer”。在你选择“确认”之前，什么都不会执行。
- **它会列出来源。** 在回答下方，你会看到它用到的候选人或面试，以及指向相应页面的链接。
- **它不会跑题。** 它只回答关于 prepza 以及用 prepza 招聘的问题，其他问题会婉拒。

### 2. 通过 MCP 在 Claude 或 ChatGPT 中使用 prepza

如果你的团队已经在 Claude 或 ChatGPT 中工作，可以把 prepza 也带到那里。prepza 的 MCP 服务器提供与内置智能助手相同的工具。

**连接步骤：**

1. 在 prepza 中打开公司的 **集成** 标签页，选择 **AI 应用**。复制服务器地址：`https://prepza.ai/mcp`。
2. **在 Claude 中：** 打开“设置”，进入“连接器”，用这个地址添加一个自定义连接器。**在 Claude Code 中：** 运行 `claude mcp add --transport http prepza https://prepza.ai/mcp`。**在 ChatGPT 中：** 在应用与连接器的设置中，把它添加为自定义连接器。
3. 你的 AI 应用会打开 prepza 的登录页面。登录后，确认是哪个应用在请求访问，然后选择 **允许**。如果只想让它读取，请先关闭 **允许更改**。

之后，像问同事一样在聊天里提问即可：“在 prepza 中，Product designer 排名前三的候选人是谁？”大多数 AI 应用会在更改前先征求你的同意，并在任何无法撤销的操作前提醒你：prepza 会告诉它们哪些操作会更改或删除内容。

**与在应用内相同的地方：**

- **你的权限。** 它以你的身份，在你所在的每家公司中，按你在各公司中的角色行事。
- **点数和限额。** 邀请一位候选人的花费与在应用内相同，邮件发送限额也一样。
- **记录。** AI 应用代你做的每件事，都会在公司的操作记录中显示为通过 AI 应用完成，从批准主题、查看结果到给予额外时间或撤销候选人。公司所有者可以在公司的 **操作记录** 标签页中查看。
- **由公司决定。** 所有者和管理员可以在公司的 AI 应用页面用 **允许在此公司使用 AI 应用** 阻止 AI 应用使用公司数据。
- **它做不到的事。** 它看不到你的密码或 API 密钥，也不能删除你的账号或公司。这些操作只能在应用内进行。

**要断开连接，** 在你的 AI 应用中删除该连接器，或在集成标签页的 **AI 应用** 下，选择该应用旁边的 **断开连接**。连接会立即失效。

**其他应用和你自己的智能体。** 开发者文档的 [MCP 标签页](/api-docs?tab=mcp)提供了 Gemini CLI、Cursor、VS Code 和 Le Chat 的接入步骤，以及用 Python 和 TypeScript 编写的完整智能体示例。在服务器上运行、无人批准登录的智能体，使用带有 **用于 AI 智能体 (MCP)** 权限的公司 API 密钥：它只在该公司内有效，并且只能使用密钥其他权限所允许的工具。

### 3. 通过 API 在你自己的平台中使用

对于不需要 AI 的自动化，prepza 提供 API，详见其[开发者文档](/api-docs)。

1. 由所有者或管理员打开公司的 **集成** 标签页，进入 **API**，选择 **新建密钥**。用将要使用它的平台来命名，选择过期时间，并只勾选它需要的权限：仪表板的密钥只需查看，招聘网站的密钥还需邀请。之后可以取消权限，但不能再添加。密钥只显示一次，请妥善保存。
2. 你的平台使用这个密钥发送请求：列出公司的面试，列出或读取候选人及其成绩、是否通过和诚信预警，以及邀请候选人。
3. 添加一个 **Webhook**：这是你的平台上的一个地址，当候选人开始、完成、邀请未能送达、邀请过期或被移除时，以及面试准备就绪时，prepza 都会向它发送带签名的请求，这样你就不必反复查询。API 页面可以向它发送测试事件，并显示它的投递日志。

每位候选人都附带一个指向其在 prepza 中完整结果的链接；在完成之前，还附带其专属的邀请链接，所以如果你愿意，可以让你的平台用自己的消息发送这个链接。如果你的平台已经知道候选人是谁，可以免登录邀请：prepza 不会发送任何邮件，候选人无需登录 prepza 即可通过链接参加面试，所以请只把链接发给候选人本人。邀请还可以在完成页面上放一个按钮，把候选人带回你的网站，并设置采用你公司颜色的浅色或深色主题。借助 prepza 的 SDK，你自己的页面可以直接展示面试。把候选人带回你的网站和在你的网站上展示面试需要公司已通过验证，并且只在公司的网站域名上有效。

这里的规则和其他地方一样：成绩用来辅助人的决定，所以不要仅凭成绩自动淘汰候选人。

## 什么时候用哪一种

先想清楚由谁来做、多久做一次。

| 你的情况 | 使用 |
| --- | --- |
| 你正在用 prepza，想快速得到答案：谁通过了、谁还没开始、还剩多少点数 | 内置智能助手 |
| 你想用几句话完成设置：根据职位描述创建面试、设置及格线、增加时间 | 内置智能助手 |
| 你整天都在 Claude 或 ChatGPT 里工作，希望在那里也能用 prepza | MCP |
| 任务既需要 prepza，也需要别的东西：你的文档、邮件草稿、其他已连接的工具 | MCP |
| 在外奔波的招聘专员想用手机上的 AI 应用查看招聘进展 | MCP |
| 你的招聘官网或 HR 系统应当自动邀请候选人，无需任何人点击 | API |
| 候选人一完成，结果就应该进入你自己的数据库或仪表盘 | API，配合 Webhook |
| 你的 ATS 是 prepza 可以对接的系统（Workable、Greenhouse、Teamtailor、Recruitee、Breezy HR） | 都不需要：在集成标签页中连接 ATS 即可。参见[如何把技能测试接入 ATS](/guides/ats-integration-skills-tests) |

一个简单的经验法则：

- **由人提问，并检查每一项更改：** 用 prepza 中的智能助手；如果这个人整天在 Claude 或 ChatGPT 里工作，就用 MCP。
- **由软件自行运行，每次都以相同方式执行：** 用 API。
- **刚开始使用：** 先试试内置智能助手。它无需任何设置，而且学到的用法可以直接用在 MCP 上。

它们也可以搭配使用。团队可以通过 API 从 HR 系统发送邀请，招聘专员则向智能助手或自己的 AI 聊天询问结果。

## 怎样获得好的结果

- **说出名称。**“Senior Backend 面试”比“那场面试”效果更好。
- **重要的事一次只要求一步。** 先检查结果，再提出下一步。
- **允许之前先看清审批内容。** 它会准确显示将要执行什么。
- **问清数字从哪里来。** 好的智能体能指出数字背后的候选人或页面。
- **决定留给人来做。** 用智能体来查找、排序和准备；决定由你自己来做。

## 价格

内置智能助手、MCP 连接和 API 都可以免费使用。你只需和往常一样为候选人付费：按至少回答了一道题的候选人计费，没有订阅。参见[价格](/pricing)。
