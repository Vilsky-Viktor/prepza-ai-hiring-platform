# 如何把技能测试接入 ATS

大多数招聘团队在招聘管理系统（ATS）里管理候选人，却在另一个工具里做技能测试。两者没有打通时，就得有人从 ATS 里复制邮箱、手动发送邀请、等待，再把分数抄回去。五位候选人时还应付得过来。到了五十位，邀请发得晚，结果躺在一个没人打开的标签页里，优秀的求职者在等待中接受了别家的 offer。

本指南说明 ATS 与测试工具之间好的对接能做什么、在依赖它之前要检查什么，以及如何设置，让自动化处理繁琐的事务，而每一个招聘决定仍由人来做。

## 为什么要打通

| 没有对接 | 有对接 |
| --- | --- |
| 有人导出或复制候选人的邮箱 | 把候选人移到某个阶段就会发出邀请 |
| 有人有空时才发邀请 | 移动后几分钟内就发出邀请 |
| 结果留在测试工具里 | 结果显示在 ATS 的候选人记录上 |
| 用人经理问：“有人测过他们吗？” | ATS 显示谁做了测试、成绩如何 |
| 邮箱拼错，候选人被漏掉 | ATS 是所有申请人的唯一名单 |

速度比看上去更重要。从申请到收到回复的间隔越长，退出流程或接受其他工作的候选人就越多。确切的流失率因岗位和市场而差别很大，所以对公开的数字要谨慎看待，但方向是一致的：流程慢就会流失人才，而最优秀的求职者通常选择也最多。

## 好的流程是什么样的

靠谱的对接会沿用你已有的招聘阶段，而不是另造一套流程。

1. **候选人提交申请**，像平常一样进入你的 ATS。
2. **由人把候选人移到测试阶段**，例如“技能测试”。这个移动就是触发条件，所以谁来做测试仍由人决定。
3. **测试工具自动发送邀请**，邀请候选人参加与该职位关联的测试。
4. **候选人在自己方便的时间完成测试**，只要在你设定的截止时间之内。
5. **结果写回 ATS 的候选人记录**：分数、是否通过、诚信预警，以及查看完整回答的链接。
6. **由人查看结果**，决定是否推进候选人。

有两件事刻意保留为人工操作：选择谁来做测试，以及决定下一步怎么做。对接只是省掉了中间的复制粘贴。

### 为什么不在每份新申请进来时就触发？

有些工具会邀请所有申请人。对于所有申请人都做同一份测试的大批量招聘岗位，这样做也许可以。但以你主动移入候选人的阶段作为触发条件更容易掌控：你可以跳过明显不符合硬性要求的申请人（没有工作许可、地点不符），也永远不会去测试、更不会为本来就要淘汰的人付费。

## 选择对接方案前要检查什么

并不是每一句“可与你的 ATS 集成”都意味着同样的东西。在接入任何东西之前，先问清这些问题。

| 问题 | 为什么重要 | 好的答案 |
| --- | --- | --- |
| 怎么连接？ | 共享密码和由供应商持有的账号难以审计或撤销 | 由你的公司创建、随时可以删除的 API 密钥或令牌 |
| 密钥能做什么？ | 拥有完全权限的密钥一旦泄露就是风险 | 对接所需的最小权限，并在文档中列明 |
| 什么会触发邀请？ | 你需要确切知道候选人何时会收到邮件 | 你为每个职位选定的特定阶段 |
| 结果出现在哪里？ | 没人看到的结果毫无用处 | 在候选人资料上，作为团队本来就会看的备注或评论 |
| 邀请发送失败会怎样？ | 点数用完、拼写错误、账号暂停：候选人悄无声息地卡住 | 会通知到相关人员，并且可以重新邀请候选人 |
| 同一事件会被处理两次吗？ | ATS 会重发事件；候选人不应收到两封邀请 | 无论事件到达多少次，每位候选人每个测试只被邀请一次 |
| 如何验证收到的事件？ | 未经验证的地址可能被发送伪造的事件 | 工具会校验的签名请求 |
| 候选人数据保留多久？ | GDPR 等数据保护法规要求有明确的保留期限 | 有明确的期限，并在你删除职位、测试或账号时一并删除 |
| 费用是多少？ | 按席位收费的套餐会让自动化变得昂贵 | 按每位受测候选人计算、可预测的费用 |

如果供应商无法清楚地回答关于失败和重复事件的问题，那你多半会在吃过亏之后才知道答案。

### 数据保护

打通两个系统，意味着候选人数据（至少是姓名和邮箱）会在两家公司之间传递。根据 GDPR 及类似法律，测试供应商通常是你的数据处理者，因此你需要签订数据处理协议，并在隐私声明或邀请中告知候选人，技能测试是招聘流程的一部分。传递的数据仅限测试所需的最少内容。关于测试和招聘中使用 AI 的法律问题，请参阅[在欧盟使用 AI 招聘合法吗？](/guides/is-ai-hiring-legal-in-the-eu)

## 设置清单

在为正式招聘的职位开启之前：

1. **在 ATS 中建一个专门用于测试的阶段**，例如“技能测试”。不要复用一个有其他含义的阶段，否则候选人会被误发邀请。
2. **用管理员账号创建密钥**，该账号要能看到所有你想关联的职位，并且只授予文档列出的权限。
3. **把每个职位关联到对应的测试**，并选择触发邀请的阶段。
4. **设置 Webhook**：如果你的 ATS 需要手动设置，就把它的签名密钥粘贴到工具要求的位置。
5. **先拿自己测试**。用你自己的邮箱添加一位候选人，把他移到该阶段，完成测试，然后检查备注是否出现在 ATS 中。
6. **确定谁来盯着失败**：邀请发不出去时通知谁，由谁来处理。
7. **约定如何解读结果**。及格线是参考，不是自动淘汰。在结果出来之前就定好，而不是之后。

## 常见错误

- **自动化的是决定，而不是事务性工作**。把低于某个分数的人全部自动淘汰，就去掉了人工把关，而正是人工把关能发现有问题的题目，或者遇到网络问题的候选人。让分数来排序，让人来做决定。
- **用错了触发阶段**。招聘专员出于其他目的使用的阶段，会把测试发给不该收到的人。
- **所有职位用同一份测试**。对接让你很容易到处发送同一份测试。但测试只有针对具体岗位设计时才最有用。参见[技能测试与简历筛选对比](/guides/skills-tests-vs-cv-screening)。
- **没人盯着失败**。如果邀请悄悄发送失败，候选人会一直等一封永远不会来的邮件，而你还以为他没理会。
- **密钥绑定在要离职的人身上**。有些 ATS 密钥以创建者的身份运行。那个人的账号被关闭后，对接就会停止。请使用会长期保留的账号，并在人员调岗时重新连接。
- **忘了 ATS 之外的候选人**。内推候选人和直接申请、从未进入 ATS 的人同样需要邀请。也要保留一种手动邀请的方式。

## prepza 怎么做

prepza 可对接 **Workable、Greenhouse、Teamtailor、Recruitee 和 Breezy HR**，并遵循上面描述的流程。

- **你的密钥，你来掌控**。所有者或管理员在公司的“集成”标签页中，用你的公司在 ATS 中创建的密钥连接 ATS。prepza 会在保存前验证密钥，加密存储，之后不再显示。断开连接会立即删除密钥和已关联的职位。
- **把职位关联到面试**。选择一个 ATS 职位和触发邀请的阶段，然后把它关联到 prepza 中已有的面试，或根据 ATS 中的职位描述新建一个面试。在写出任何题目之前，你会先审核主题。
- **移动候选人，邀请随即发出**。即使 ATS 把同一事件发送两次，每位候选人每场面试也只会被邀请一次。
- **结果回到 ATS**。候选人完成后，prepza 会在 ATS 中为其添加一条备注或评论，内容包括成绩、是否通过、诚信预警（离开页面、尝试复制、答题快到不可能读完题目）以及包含全部回答的评分卡链接。
- **失败不会被忽视**。如果无法邀请某位候选人，例如公司点数用完、达到邮件发送上限或 prepza 暂时暂停了邀请，公司的所有成员都会收到一条注明 ATS 名称的通知。因点数不足而未被邀请的候选人会在充值后自动收到邀请，任何职位中等待的候选人都可以一键重新邀请。
- **如果你用 Slack**。prepza 可以把通知（例如某位候选人已完成，或某位 ATS 候选人无法被邀请）发到你选择的 Slack 频道。
- **你自己的平台**。如果你的 ATS 不在列表中，可以通过 prepza 的 [API](/api-docs) 用 API 密钥邀请候选人，并在候选人开始、完成、邀请未能送达、邀请过期或被移除时，以及面试准备就绪时收到签名的 Webhook。
- **数据按固定期限保存**。从 ATS 保存的候选人会在 365 天后删除；如果其面试或公司被删除，则会更早删除。

有些 ATS 需要在其一侧操作一步。Greenhouse、Teamtailor 和 Recruitee 需要你手动添加 Webhook；prepza 的“说明”对话框会显示地址以及粘贴签名密钥的位置。Workable 和 Breezy HR 的 Webhook 由 prepza 自动设置。

按候选人计费，没有订阅：你只需为至少回答了一道题的候选人付费，充值 $50 时每人 $5，充值 $200 起每人 $4，充值 $600 起每人 $3，充值 $1,000 起每人 $2。此处价格以美元计，在加拿大、澳大利亚、以色列、波兰、瑞士、日本、韩国、台湾、香港、泰国、新加坡、印度、欧洲其他地区和英国则以当地货币计；增值税或销售税在结账时处理。连接 ATS 和创建面试都是免费的，你的第一家公司的前 3 位候选人免费。参见[价格](/pricing)。
