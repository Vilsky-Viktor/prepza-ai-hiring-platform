# 역량 테스트를 ATS와 연동하는 방법

대부분의 채용팀은 지원자를 채용 관리 시스템(ATS)에서 관리하고, 역량 테스트는 다른 도구에서 진행합니다. 둘이 연결되어 있지 않으면 누군가 ATS에서 이메일 주소를 복사해 초대를 직접 보내고, 기다렸다가, 점수를 다시 옮겨 적어야 합니다. 지원자가 5명이면 그래도 됩니다. 50명이 되면 초대가 늦게 나가고, 결과는 아무도 열지 않는 두 번째 탭에 쌓이며, 좋은 지원자는 기다리는 동안 다른 회사의 오퍼를 받아들입니다.

이 가이드에서는 ATS와 테스트 도구를 잘 연동하면 무엇이 달라지는지, 연동에 의존하기 전에 무엇을 확인해야 하는지, 그리고 번거로운 작업은 자동화에 맡기면서 모든 채용 결정은 사람이 내리도록 설정하는 방법을 설명합니다.

## 왜 연동해야 할까

| 연동하지 않을 때 | 연동할 때 |
| --- | --- |
| 누군가 지원자 이메일을 내보내거나 복사한다 | 지원자를 특정 단계로 옮기면 초대가 발송된다 |
| 누군가 시간이 날 때 초대가 나간다 | 단계를 옮긴 뒤 몇 분 안에 초대가 나간다 |
| 결과가 테스트 도구 안에 있다 | 결과가 ATS의 지원자 정보에 표시된다 |
| 채용 담당 매니저가 "누가 테스트해 봤나요?"라고 묻는다 | 누가 테스트를 봤고 결과가 어땠는지 ATS에서 바로 보인다 |
| 이메일 오타와 누락된 지원자 | ATS가 지원자 전체를 담은 단 하나의 목록이 된다 |

속도는 생각보다 중요합니다. 지원부터 회신까지 시간이 길어질수록 더 많은 지원자가 이탈하거나 다른 곳에 입사합니다. 정확한 이탈률은 직무와 시장에 따라 크게 다르므로 공개된 수치는 신중하게 봐야 하지만, 방향은 일관됩니다. 느린 채용 프로세스는 사람을 잃고, 가장 뛰어난 지원자일수록 보통 선택지가 가장 많습니다.

## 좋은 흐름은 어떤 모습일까

제대로 된 연동은 이미 쓰고 있는 채용 단계를 따릅니다. 새로운 프로세스를 만들어 내지 않습니다.

1. **지원자가 지원하면** 평소처럼 ATS에 등록됩니다.
2. **담당자가 지원자를 테스트 단계로 옮깁니다.** 예를 들어 "역량 테스트" 단계입니다. 이 이동이 트리거이므로, 누가 테스트를 볼지는 여전히 사람이 정합니다.
3. **테스트 도구가 초대를 자동으로 보냅니다.** 해당 채용 공고에 연결된 테스트로 초대합니다.
4. **지원자는 편한 시간에 테스트를 봅니다.** 정해 둔 기한 안이면 됩니다.
5. **결과가 ATS의 지원자 정보에 다시 기록됩니다.** 점수, 합격 여부, 부정행위 신호, 전체 답변 링크가 포함됩니다.
6. **담당자가 결과를 검토하고** 지원자를 다음 단계로 옮길지 결정합니다.

두 가지는 일부러 수동으로 남겨 둡니다. 누구에게 테스트를 보게 할지 고르는 일과 다음에 무엇을 할지 결정하는 일입니다. 연동은 그 사이의 복사 작업만 없앱니다.

### 새 지원이 들어올 때마다 보내면 안 될까?

지원자 전원을 초대하는 도구도 있습니다. 모든 지원자가 같은 테스트를 보는 대량 채용 직무라면 괜찮을 수 있습니다. 하지만 지원자를 옮겨 넣는 단계를 트리거로 쓰면 관리하기가 더 쉽습니다. 필수 요건을 명백히 충족하지 못하는 지원자(취업 허가 없음, 근무지 불일치 등)는 건너뛸 수 있고, 어차피 불합격시킬 사람을 테스트하거나 그 비용을 낼 일도 없습니다.

## 연동을 고르기 전에 확인할 것

"ATS와 연동됩니다"라는 말이 모두 같은 뜻은 아닙니다. 무엇이든 연결하기 전에 다음을 물어보세요.

| 질문 | 왜 중요한가 | 좋은 답 |
| --- | --- | --- |
| 어떻게 연결하나요? | 공유 비밀번호나 업체가 보유한 계정은 감사하거나 회수하기 어렵다 | 회사가 직접 만들고 언제든 삭제할 수 있는 API 키나 토큰 |
| 키로 무엇을 할 수 있나요? | 전체 권한을 가진 키는 유출되면 위험하다 | 연동에 필요한 최소한의 권한으로, 문서에 명시되어 있다 |
| 무엇이 초대를 보내게 하나요? | 지원자에게 언제 이메일이 가는지 정확히 알아야 한다 | 채용 공고마다 직접 고르는 특정 단계 |
| 결과는 어디에 표시되나요? | 아무도 보지 않는 결과는 쓸모없다 | 지원자 프로필에, 팀이 이미 읽는 메모나 댓글로 |
| 초대 발송에 실패하면 어떻게 되나요? | 크레딧 소진, 오타, 일시 중지된 계정 때문에 지원자가 아무도 모르게 멈춰 있게 된다 | 누군가에게 알림이 가고, 지원자를 다시 초대할 수 있다 |
| 같은 이벤트가 두 번 처리될 수 있나요? | ATS는 이벤트를 다시 보낸다. 지원자가 초대를 두 번 받아서는 안 된다 | 이벤트가 몇 번 오든 각 지원자는 테스트당 한 번만 초대된다 |
| 들어오는 이벤트는 어떻게 검증하나요? | 검증하지 않는 주소에는 가짜 이벤트를 보낼 수 있다 | 도구가 확인하는 서명된 요청 |
| 지원자 데이터는 얼마나 보관하나요? | GDPR 같은 개인정보 보호법은 명확한 보관 기간을 요구한다 | 명시된 보관 기간이 있고, 채용 공고, 테스트, 계정을 삭제하면 함께 삭제된다 |
| 비용은 얼마인가요? | 사용자 수 기준 요금제는 자동화를 비싸게 만들 수 있다 | 테스트한 지원자 1명당 예측 가능한 비용 |

업체가 실패와 중복에 관한 질문에 명확히 답하지 못한다면, 직접 문제를 겪으며 알게 될 각오를 해야 합니다.

### 개인정보 보호

두 시스템을 연동하면 지원자 데이터, 최소한 이름과 이메일 주소가 두 회사 사이를 오가게 됩니다. GDPR과 비슷한 법률에 따르면 테스트 업체는 보통 귀사의 개인정보 수탁자(처리자)이므로, 데이터 처리 계약이 필요하고, 개인정보 처리방침이나 초대 메일에서 역량 테스트가 채용 과정의 일부라는 점을 지원자에게 알려야 합니다. 넘기는 데이터는 테스트에 필요한 최소한으로 줄이세요. 테스트와 채용에서의 AI에 관한 법적 측면은 [EU에서 AI 채용은 합법인가?](/guides/is-ai-hiring-legal-in-the-eu)를 참고하세요.

## 설정 체크리스트

실제 채용 공고에 켜기 전에:

1. **ATS에 테스트 전용 단계를 만드세요.** 예를 들어 "역량 테스트"입니다. 다른 의미가 있는 단계를 재사용하면 지원자에게 실수로 초대가 나갑니다.
2. **관리자 계정에서 키를 만드세요.** 연결하려는 모든 채용 공고를 볼 수 있는 계정이어야 하며, 문서에 나온 권한만 부여합니다.
3. **각 채용 공고를 해당 테스트에 연결하고** 초대를 보내는 단계를 고르세요.
4. **웹훅을 설정하세요.** ATS에서 직접 설정해야 한다면, 웹훅의 시크릿을 도구가 요청하는 곳에 붙여 넣습니다.
5. **직접 테스트해 보세요.** 본인 이메일로 지원자를 추가하고, 그 단계로 옮긴 뒤 테스트를 보고, ATS에 메모가 나타나는지 확인합니다.
6. **실패를 누가 지켜볼지 정하세요.** 초대를 보내지 못했을 때 누가 알림을 받고 누가 해결할지 정합니다.
7. **결과를 어떻게 읽을지 합의하세요.** 합격 기준 점수는 참고 기준이지 자동 불합격 기준이 아닙니다. 결과가 들어온 뒤가 아니라 들어오기 전에 정해 두세요.

## 흔한 실수

- **서류 작업이 아니라 결정을 자동화하기.** 일정 점수 미만을 모두 자동으로 불합격시키면, 잘못된 문항이나 접속 문제를 겪은 지원자를 잡아내는 사람의 검토가 사라집니다. 정렬은 점수에 맡기고, 결정은 사람이 내리세요.
- **잘못된 단계를 트리거로 쓰기.** 리크루터가 다른 용도로 쓰는 단계라면, 테스트를 받지 말아야 할 사람에게 테스트가 나갑니다.
- **모든 공고에 같은 테스트 쓰기.** 연동하면 같은 테스트를 어디에나 보내기 쉬워집니다. 하지만 테스트는 해당 직무에 맞게 만들어졌을 때 가장 도움이 됩니다. [역량 테스트 vs 이력서 심사](/guides/skills-tests-vs-cv-screening)를 참고하세요.
- **아무도 실패를 지켜보지 않기.** 초대가 조용히 실패하면 지원자는 오지 않을 이메일을 기다리고, 회사는 지원자가 무시했다고 생각합니다.
- **퇴사할 사람에게 묶인 키.** 일부 ATS 키는 만든 사람의 권한으로 동작합니다. 그 사람의 계정이 닫히면 연동도 멈춥니다. 계속 유지될 계정을 쓰고, 담당자가 바뀌면 다시 연동하세요.
- **ATS 밖의 지원자를 잊기.** ATS에 들어오지 않는 추천 지원자나 직접 지원자에게도 초대가 필요합니다. 직접 초대하는 방법도 남겨 두세요.

## prepza는 이렇게 합니다

prepza는 **Workable, Greenhouse, Teamtailor, Recruitee, Breezy HR**과 연동되며, 위에서 설명한 흐름을 따릅니다.

- **우리 회사의 키, 우리 회사의 통제.** 소유자나 관리자가 회사의 연동 탭에서, 회사가 ATS에서 만든 키로 ATS를 연동합니다. prepza는 저장 전에 키를 확인하고, 암호화해 보관하며, 다시는 보여 주지 않습니다. 연동을 해제하면 키와 연결된 채용 공고가 즉시 삭제됩니다.
- **채용 공고를 면접에 연결.** ATS의 채용 공고와 초대를 보내는 단계를 고르고, prepza의 기존 면접에 연결하거나 ATS의 공고 내용으로 새 면접을 만듭니다. 문항이 만들어지기 전에 주제를 먼저 검토합니다.
- **지원자를 옮기면 초대가 나갑니다.** ATS가 같은 이벤트를 두 번 보내더라도 각 지원자는 면접당 한 번만 초대됩니다.
- **결과는 ATS로 돌아갑니다.** 지원자가 응시를 마치면 prepza는 ATS의 해당 지원자에게 메모나 댓글을 추가합니다. 등급, 합격 여부, 부정행위 신호(페이지 이탈, 복사 시도, 문항을 읽기에는 너무 빨리 고른 답)와 모든 답변이 담긴 평가표 링크가 포함됩니다.
- **실패를 놓치지 않습니다.** 회사의 크레딧이 소진되었거나, 이메일 한도에 도달했거나, prepza가 초대를 일시 중지해서 지원자를 초대할 수 없으면, 회사의 모든 멤버가 ATS 이름이 적힌 알림을 받습니다. 크레딧 부족으로 초대되지 못한 지원자는 충전 후 자동으로 초대되며, 어떤 공고든 대기 중인 지원자를 클릭 한 번으로 다시 초대할 수 있습니다.
- **Slack을 쓴다면.** prepza는 응시를 마친 지원자나 초대하지 못한 ATS 지원자 같은 알림을 원하는 Slack 채널에 게시할 수 있습니다.
- **자체 플랫폼도 가능합니다.** 사용하는 ATS가 목록에 없다면, prepza [API](/api-docs)로 API 키를 사용해 지원자를 초대하고, 지원자가 응시를 시작하거나 마칠 때, 초대가 전달되지 않거나 만료될 때, 지원자가 삭제될 때, 그리고 면접이 준비되었을 때 서명된 웹훅을 받을 수 있습니다.
- **정해진 기간만 보관합니다.** ATS에서 저장된 지원자는 365일 후에 삭제되며, 면접이나 회사를 삭제하면 그보다 먼저 삭제됩니다.

일부 ATS는 ATS 쪽에서 해야 할 작업이 있습니다. Greenhouse, Teamtailor, Recruitee는 웹훅을 직접 추가해야 하며, prepza의 안내 창에 주소와 시크릿을 붙여 넣을 위치가 표시됩니다. Workable과 Breezy HR의 웹훅은 prepza가 직접 설정합니다.

요금은 지원자 기준이며 구독은 없습니다. 최소 한 문항 이상 답한 지원자에 대해서만 비용을 내며, $50 충전 시 지원자당 $5, $200 충전부터 $4, $600 충전부터 $3, $1,000 충전부터 $2입니다. 가격은 여기서는 미국 달러, 캐나다, 호주, 이스라엘, 폴란드, 스위스, 일본, 한국, 대만, 홍콩, 태국, 싱가포르, 인도, 그 밖의 유럽, 영국에서는 현지 통화 기준이며, 부가가치세나 판매세는 결제 시 처리됩니다. ATS 연결과 면접 생성은 무료이며, 첫 회사의 처음 지원자 3명은 무료입니다. [요금](/pricing)을 참고하세요.
