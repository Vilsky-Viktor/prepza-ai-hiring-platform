# スキルテストを ATS と連携する方法

多くの採用チームは、候補者を採用管理システム（ATS）で管理し、スキルテストは別のツールで実施しています。両者がつながっていないと、誰かが ATS からメールアドレスをコピーし、手作業で招待を送り、結果を待ち、スコアを ATS に書き戻すことになります。候補者が 5 人ならそれでも回ります。50 人になると、招待は遅れ、結果は誰も開かない別タブに埋もれ、優秀な応募者は待っている間に他社の内定を受けてしまいます。

このガイドでは、ATS とテストツールの良い連携が何をするのか、頼る前に何を確認すべきか、そして面倒な作業は自動化に任せつつ、採用の判断はすべて人が行うように設定する方法を説明します。

## そもそもなぜ連携するのか

| 連携なし | 連携あり |
| --- | --- |
| 誰かが候補者のメールアドレスをエクスポートまたはコピーする | 候補者を選考ステップに移すと招待が送られる |
| 誰かに時間ができたときに招待が送られる | 移動から数分以内に招待が送られる |
| 結果はテストツールの中にある | 結果が ATS の候補者情報に表示される |
| 採用責任者が「誰かテストした？」と聞いてくる | 誰がテストを受け、結果がどうだったかを ATS で確認できる |
| メールアドレスの入力ミスや候補者の見落とし | ATS が応募者の唯一のリストになる |

スピードは見た目以上に重要です。応募から連絡までの間が空くほど、選考を辞退したり、別の仕事に決めたりする候補者が増えます。正確な離脱率は職種や市場によって大きく異なるため、公表されている数字は慎重に扱うべきですが、傾向は一貫しています。選考が遅いと人を失い、最も優秀な応募者ほど選択肢が多いのが普通です。

## 良い流れとは

しっかりした連携は、すでに使っている選考ステップに沿って動きます。新しいプロセスを作り出すことはしません。

1. **候補者が応募し**、いつもどおり ATS に登録されます。
2. **担当者が候補者をテスト用の選考ステップに移します**。たとえば「スキルテスト」です。この移動がきっかけになるので、誰にテストを受けてもらうかは引き続き人が決めます。
3. **テストツールが招待を自動で送ります**。その求人に紐付いたテストへの招待です。
4. **候補者は都合のよい時間にテストを受けます**。設定した期限内であればいつでも構いません。
5. **結果が ATS の候補者情報に書き戻されます**。スコア、合格かどうか、不正の兆候、すべての回答へのリンクです。
6. **担当者が結果を確認し**、候補者を次に進めるかどうかを決めます。

意図的に手作業のまま残すのは 2 つです。誰にテストを受けてもらうかを選ぶことと、次に何をするかを決めることです。連携がなくすのは、その間のコピー作業だけです。

### なぜ新しい応募のたびに送らないのか

応募者全員を招待するツールもあります。全員が同じテストを受ける大量採用の職種なら、それでも問題ない場合があります。しかし、候補者を移す選考ステップをきっかけにしたほうが管理しやすくなります。必須条件を明らかに満たしていない応募者（就労許可がない、勤務地が合わないなど）を飛ばせますし、どのみち不採用にする人にテストを受けてもらうことも、その費用を払うこともありません。

## 連携を選ぶ前に確認すること

「ATS と連携できます」という言葉が、いつも同じ意味とは限りません。何かを接続する前に、次の点を確認しましょう。

| 質問 | なぜ重要か | 良い答え |
| --- | --- | --- |
| どうやって接続するのか？ | 共有パスワードやベンダーが持つアカウントは、監査も取り消しも難しい | 自社で作成し、いつでも削除できる API キーまたはトークン |
| キーで何ができるのか？ | フルアクセスのキーは、漏えいしたときのリスクになる | 連携に必要な最小限の権限で、ドキュメントに明記されている |
| 何が招待のきっかけになるのか？ | 候補者にいつメールが届くのかを正確に知る必要がある | 求人ごとに自分で選ぶ特定の選考ステップ |
| 結果はどこに表示されるのか？ | 誰も見ない結果は役に立たない | 候補者のプロフィールに、チームがすでに読んでいるメモやコメントとして |
| 招待が失敗したらどうなるのか？ | クレジット切れ、入力ミス、一時停止中のアカウントなどで、候補者が誰にも気づかれずに止まってしまう | 誰かに通知が届き、候補者を再招待できる |
| 同じイベントが 2 回処理されることはあるか？ | ATS はイベントを再送する。候補者に招待が 2 通届くべきではない | イベントが何度届いても、各候補者はテストごとに 1 回だけ招待される |
| 受信したイベントはどう検証されるのか？ | 検証のない受信先には偽のイベントを送れてしまう | ツールが検証する署名付きリクエスト |
| 候補者のデータはどのくらい保存されるのか？ | GDPR などの個人情報保護法は、明確な保存期間を求めている | 明示された保存期間があり、求人、テスト、アカウントを削除すると削除される |
| 費用はいくらか？ | ユーザー数課金のプランでは、自動化が高くつくことがある | テストした候補者 1 人あたりの予測できる費用 |

ベンダーが失敗と重複についての質問に明確に答えられない場合は、痛い目にあって知ることになると思っておきましょう。

### データ保護

2 つのシステムを連携すると、候補者のデータ、少なくとも氏名とメールアドレスが 2 つの会社の間でやり取りされます。GDPR や同様の法律では、テストのベンダーは通常あなたの会社のデータ処理者にあたるため、データ処理契約が必要です。また、プライバシーポリシーや招待の中で、選考にスキルテストが含まれることを候補者に伝えましょう。渡すデータは、テストに必要な最小限にとどめます。テストや採用での AI の法的な側面については、[EU で AI 採用は合法か？](/guides/is-ai-hiring-legal-in-the-eu)をご覧ください。

## 設定のチェックリスト

実際の求人で有効にする前に、次の点を確認しましょう。

1. **ATS にテスト専用の選考ステップを作ります。**「スキルテスト」などです。別の意味を持つ選考ステップを使い回すと、候補者に誤って招待が送られます。
2. **管理者アカウントからキーを作成します**。連携したいすべての求人が見えるアカウントで、ドキュメントに記載された権限だけを付けます。
3. **各求人をそのテストに紐付け**、招待のきっかけになる選考ステップを選びます。
4. **Webhook を設定します**。ATS で手動設定が必要な場合は、そのシークレットをツールが求める場所に貼り付けます。
5. **自分で試します**。自分のメールアドレスで候補者を追加し、その選考ステップに移してテストを受け、ATS にメモが表示されることを確認します。
6. **失敗を誰が見張るかを決めます**。招待を送れなかったときに誰に通知が届き、誰が対処するかです。
7. **結果の読み方を決めておきます**。合格ラインは目安であり、自動的な不採用ではありません。結果が届いてからではなく、届く前に決めておきましょう。

## よくある間違い

- **事務作業ではなく判断を自動化してしまう**。一定のスコア未満を全員自動で不採用にすると、問題のある設問や、通信トラブルにあった候補者に気づく人のチェックがなくなります。スコアで並べ替え、判断は人が行いましょう。
- **間違った選考ステップをきっかけにしてしまう**。採用担当者が別の目的で使っている選考ステップだと、受けるべきでない人にテストが送られます。
- **すべての求人に同じテストを使う**。連携すると、同じテストをどこにでも送るのが簡単になります。しかしテストが最も役立つのは、その職種のために作られたときです。[スキルテストと書類選考の比較](/guides/skills-tests-vs-cv-screening)をご覧ください。
- **誰も失敗を見張っていない**。招待が気づかれないまま失敗すると、候補者は届かないメールを待ち続け、あなたは候補者が無視したと思い込みます。
- **退職する人に紐付いたキーを使う**。ATS のキーの中には、作成した人として動作するものがあります。その人のアカウントが閉じられると、連携は止まります。残り続けるアカウントを使い、担当が変わったら接続し直しましょう。
- **ATS の外にいる候補者を忘れる**。ATS に登録されないリファラルや直接応募の候補者にも招待が必要です。手動で招待する方法も残しておきましょう。

## prepza の場合

prepza は **Workable、Greenhouse、Teamtailor、Recruitee、Breezy HR** と連携し、上で説明した流れに沿って動きます。

- **自社のキーを自社で管理**。所有者または管理者が、会社の「連携」タブで、自社が ATS で作成したキーを使って ATS を接続します。prepza は保存前にキーを確認し、暗号化して保存し、その後は二度と表示しません。接続を解除すると、キーと紐付いた求人がすぐに削除されます。
- **求人を面接に紐付ける**。ATS の求人と招待のきっかけになる選考ステップを選び、prepza の既存の面接に紐付けるか、ATS の求人本文から新しい面接を作成します。設問が作られる前に、テーマをあなたが確認します。
- **候補者を移せば招待が届く**。ATS が同じイベントを 2 回送っても、各候補者は面接ごとに 1 回だけ招待されます。
- **結果は ATS に戻る**。候補者が回答を終えると、prepza は ATS の候補者にメモまたはコメントを追加します。内容は評価、合格かどうか、不正の兆候（ページから離れた、コピーしようとした、設問を読む時間がないほど速く回答を選んだ）と、すべての回答が載ったスコアカードへのリンクです。
- **失敗を見逃さない**。会社のクレジットが切れた、メール送信の上限に達した、prepza が招待を一時停止しているなどの理由で候補者を招待できない場合、会社のメンバー全員に ATS 名入りのお知らせが届きます。クレジット不足で招待されなかった候補者はチャージ後に自動で招待され、どの求人の待機中の候補者もワンクリックで再招待できます。
- **Slack を使っているなら**。prepza は、回答を終えた候補者や、招待できなかった ATS の候補者などのお知らせを、選んだ Slack チャンネルに投稿できます。
- **自社のプラットフォームでも**。お使いの ATS が一覧にない場合は、prepza の [API](/api-docs) を使えば、API キーで候補者を招待し、候補者が回答を開始・完了したとき、招待が届かなかったとき、招待の期限が切れたとき、削除されたとき、そして面接の準備ができたときに署名付きの Webhook を受け取れます。
- **データの保存期間は決まっています**。ATS から保存された候補者は 365 日後に削除されます。面接や会社を削除した場合は、それより前に削除されます。

ATS によっては、ATS 側での作業が必要です。Greenhouse、Teamtailor、Recruitee では Webhook を手動で追加する必要があり、prepza の「手順」ダイアログに、アドレスとシークレットの貼り付け先が表示されます。Workable と Breezy HR の Webhook は prepza が自動で設定します。

料金は候補者単位で、サブスクリプションはありません。1 問以上回答した候補者の分だけお支払いいただきます。$50 のチャージでは 1 人 $5、$200 以上のチャージでは $4、$600 以上のチャージでは $3、$1,000 以上のチャージでは $2 です。価格はここでは米ドルで、カナダ、オーストラリア、イスラエル、ポーランド、スイス、日本、韓国、台湾、香港、タイ、シンガポール、インド、その他のヨーロッパ、英国では現地通貨で、VAT や売上税は支払い時に処理されます。ATS の接続と面接の作成は無料で、最初の会社の最初の 3 人の候補者は無料です。[料金](/pricing)をご覧ください。
