# ШІ-агенти, MCP і API: що це таке і як використовувати їх у наймі

Більшість людей уперше познайомилися зі ШІ у вікні чату: ви питаєте, він відповідає. ШІ-агент іде на крок далі. Він може знаходити інформацію у ваших інструментах і на ваше прохання виконувати в них дії: створити співбесіду, запросити список кандидатів, підказати, у кого був найвищий результат минулого тижня. Model Context Protocol (MCP) — це стандарт, який дає змогу ШІ-чату, яким ви вже користуєтеся, наприклад Claude чи ChatGPT, підключатися до таких інструментів. А API — старіший і точніший спосіб, у який одна програма спілкується з іншою, без ШІ посередині.

У цьому посібнику простими словами пояснено, що таке всі три, чим вони корисні в наймі, чого варто остерігатися і як використовувати їх із prepza.

## Що таке ШІ-агент

Чат-бот лише пише текст. Агент — це мовна модель з **інструментами**: невеликими чітко визначеними діями, які вона може викликати, наприклад «показати кандидатів цієї співбесіди» або «запросити цей email». Коли ви щось питаєте, агент вирішує, які інструменти використати, читає, що вони повернули, і відповідає на цій основі, а не з пам'яті.

| Чат-бот | ШІ-агент |
| --- | --- |
| Відповідає на основі того, чого навчився під час тренування | Відповідає за вашими актуальними даними, прочитаними через інструменти |
| Може лише описати, як щось зробити | Може зробити це сам, коли ви попросите й дозволите |
| Вигадує, коли не знає | Перевіряє або каже, що не може |
| Живе в одному вікні | Працює всередині інструментів, до яких ви його підключили |

Саме інструменти роблять агента корисним — і саме від них залежить, безпечний він чи ні. Хороший агент може використовувати лише надані йому інструменти, лише з вашими правами і робить лише те, про що ви попросили.

## Що таке MCP

Model Context Protocol — відкритий стандарт, який Anthropic представила наприкінці 2024 року. Тепер його підтримують Claude, ChatGPT і багато інших ШІ-застосунків та інструментів для розробників. Його часто порівнюють із портом USB-C для ШІ: замість того щоб кожен ШІ-застосунок будував власне підключення до кожного інструмента, інструмент пропонує один **MCP-сервер**, і будь-який ШІ-застосунок, що підтримує MCP, може ним користуватися.

MCP-сервер повідомляє ШІ-застосунку три речі:

1. **Які інструменти є** — з назвою, описом і даними, потрібними кожному з них.
2. **Які інструменти лише читають,** а які щось змінюють, щоб ШІ-застосунок міг запитати вас перед зміною.
3. **Хто ви** — через вхід, який ви схвалюєте один раз, щоб кожен виклик виконувався від вашого імені та з вашими правами.

Для вас це означає, що з інструментом можна працювати просто з чату, яким ви вже користуєтеся, не копіюючи дані між вікнами.

## Що таке API і чим він відрізняється

API (інтерфейс програмування застосунків) — це набір фіксованих запитів, які одна програма може надсилати іншій: «показати кандидатів цієї співбесіди», «запросити цей email». Ваші розробники пишуть код, який їх надсилає. ШІ тут не бере участі: той самий запит завжди робить те саме, а це саме те, що потрібно для автоматизації, яка працює сама.

| | Міра, ШІ-асистентка (у застосунку) | MCP (у Claude чи ChatGPT) | API |
| --- | --- | --- | --- |
| Хто користується | Ви, у prepza | Ви, у своєму ШІ-чаті | Код вашої платформи |
| Як ви просите | Своїми словами | Своїми словами | Фіксованими запитами, які пише розробник |
| Хто схвалює зміни | Ви, на картці | Ви, у своєму ШІ-застосунку | Ваш код, як його написано |
| Найкраще для | Швидких запитань і завдань | Роботи з prepza разом з іншими інструментами й файлами | Автоматизації, яка працює без нагляду |
| Входить як | Ви | Ви | Ключ компанії |

Використовуйте Міру або MCP, коли в процесі бере участь людина. Використовуйте API, коли ваша власна система має сама запрошувати кандидатів і збирати результати, наприклад із кар'єрного сайту чи внутрішнього HR-інструмента.

## Чим це корисно в наймі

У наймі багато дрібних повторюваних кроків, розкиданих різними інструментами. Агент добре дає раду саме їм:

- **Запитання про воронку.** «Які кандидати на Senior Backend пройшли цього тижня?», «Хто ще не почав співбесіду?», «Яка в нас середня оцінка на роль аналітика даних?»
- **Налаштування.** «Створи співбесіду за цим описом вакансії», «Встанови прохідний бал 70%», «Дай цьому кандидатові на 50% більше часу».
- **Масові дії.** «Запроси цих 12 людей на співбесіду Frontend» — зі списком, вставленим просто з листа чи таблиці.
- **Поєднання джерел.** У Claude чи ChatGPT можна поєднувати prepza з іншими підключеними інструментами й файлами: порівняти опис вакансії з ваших документів із темами співбесіди або підготувати чернетку листа кандидатам із шортлиста.

Чого він робити не повинен, то це ухвалювати рішення про найм. Оцінка допомагає людині скласти судження, але не замінює його. Доручайте агентові сортувати, підсумовувати й готувати, а рішення залишайте за людиною. Чому це важливо і з юридичного погляду, читайте в статті [Чи законний найм за допомогою ШІ в ЄС?](/guides/is-ai-hiring-legal-in-the-eu)

## Чого варто остерігатися

Підключення ШІ до даних про найм потребує тієї самої обережності, що й надання доступу колезі.

| Ризик | Що допомагає |
| --- | --- |
| Агент робить не те, що ви мали на увазі | Зміни спершу потребують вашого схвалення, і він робить лише те, про що ви попросили |
| Він бачить більше, ніж слід | Він діє від вашого імені: бачить те саме, що й ви, і не більше |
| Інструкції, сховані в даних | Імена, відповіді й документи кандидатів — це дані, а не інструкції до виконання |
| Секрети потрапляють у чат | API-ключі та паролі ніколи не проходять через чат |
| Незворотні помилки | Видалення акаунта чи компанії залишається в застосунку, за окремим підтвердженням |
| Дані залишають ваші інструменти | Дані потрапляють у підключений ШІ-застосунок на умовах цього застосунку: підключайте лише ті застосунки, які дозволяє ваша компанія |
| Неконтрольоване використання | Обмеження на кількість дій за годину |

Перш ніж підключати будь-який ШІ-застосунок до робочих даних, перевірте політику вашої компанії щодо ШІ-інструментів і вкажіть у повідомленні про конфіденційність для кандидатів, які сервіси обробляють їхні дані.

## Три способи працювати з prepza поза її сторінками

### 1. Міра, вбудована ШІ-асистентка

Виберіть **запитати Міру** в шапці будь-якої сторінки. Міра, ШІ-асистентка prepza, знає ваші компанії, співбесіди, кандидатів, кредити й інтеграції, а також те, як працює prepza. Вона відповідає вашою мовою, а запитання можна написати або промовити.

- **Він відповідає за вашими даними** і бачить те саме, що й ви: адміністратор бачить те, що бачить адміністратор, спостерігач — те, що бачить спостерігач.
- **Він знає, на якій ви сторінці.** Запитайте «Що можна зробити на цій сторінці?», щоб отримати посібник до цієї сторінки, або «Хто тут найкращий?» на сторінці кандидатів співбесіди, і він відповість про цю співбесіду, не перепитуючи, про яку йдеться.
- **Він готує зміни, а ви їх підтверджуєте.** Якщо попросити його запросити кандидатів, він покаже картку з тим, що саме станеться, наприклад «Запросити 12 кандидатів на співбесіду Backend-розробник». Нічого не виконується, доки ви не натиснете «Підтвердити».
- **Він показує джерела.** Під відповіддю ви бачите кандидатів або співбесіди, на які він спирався, і посилання на сторінку, звідки їх узято.
- **Він не відходить від теми.** Він відповідає про prepza і найм із нею, а від решти відмовляється.

### 2. prepza в Claude чи ChatGPT через MCP

Якщо ваша команда вже працює в Claude чи ChatGPT, prepza можна підключити туди. MCP-сервер prepza пропонує ті самі інструменти, що й Міра, вбудована асистентка.

**Як підключити:**

1. У prepza відкрийте вкладку **Інтеграції** компанії та виберіть **ШІ-застосунки**. Скопіюйте адресу сервера: `https://prepza.ai/mcp`.
2. **У Claude:** відкрийте «Налаштування», потім «Конектори» і додайте власний конектор із цією адресою. **У Claude Code:** виконайте `claude mcp add --transport http prepza https://prepza.ai/mcp`. **У ChatGPT:** додайте його як власний конектор у налаштуваннях застосунків і конекторів.
3. Ваш ШІ-застосунок відкриє сторінку входу prepza. Увійдіть, перевірте, який застосунок просить доступ, і натисніть **Дозволити**. Щоб застосунок міг лише читати, спершу вимкніть **Дозволити зміни**.

Відтепер просто питайте в чаті, як спитали б колегу: «Хто в prepza три найкращі кандидати на продуктового дизайнера?» Більшість ШІ-застосунків запитують вас перед зміною і попереджають перед будь-якою незворотною дією: prepza повідомляє їм, які дії щось змінюють або видаляють.

**Що залишається таким самим, як у застосунку:**

- **Ваші права.** Підключення діє від вашого імені в усіх компаніях, де ви є, з вашою роллю в кожній.
- **Кредити й ліміти.** Запрошення кандидата коштує стільки ж, скільки в застосунку, і діють ті самі ліміти на листи.
- **Журнал.** Усе, що ШІ-застосунок робить за вас, показується в журналі дій компанії як зроблене через ШІ-застосунок: від схвалення тем і перегляду результатів до надання додаткового часу чи відкликання кандидата. Власник компанії читає його на вкладці **Журнал дій** компанії.
- **Вирішує компанія.** Власники й адміністратори можуть заборонити ШІ-застосункам використовувати дані компанії перемикачем **Дозволити ШІ-застосунки в цій компанії** на її сторінці ШІ-застосунків.
- **Чого підключення не може.** Воно не бачить ваш пароль і API-ключі й не може видалити ваш акаунт чи компанію. Це залишається в застосунку.

**Щоб відключити,** видаліть конектор у своєму ШІ-застосунку або натисніть **Відключити** поруч із ним у розділі **ШІ-застосунки** на вкладці «Інтеграції». Він одразу перестане працювати.

**Інші застосунки та ваші власні агенти.** На [вкладці MCP](/api-docs?tab=mcp) документації для розробників є кроки для Gemini CLI, Cursor, VS Code і Le Chat, а також повні приклади агентів на Python і TypeScript. Агент, який працює на сервері, де нікому підтвердити вхід, використовує API-ключ компанії з правом **Використання з ШІ-агентами (MCP)**: він працює лише в цій компанії й лише з тими інструментами, які дозволяють інші права ключа.

### 3. Ваша власна платформа через API

Для автоматизації без ШІ prepza має API, описаний у її [документації для розробників](/api-docs).

1. Власник або адміністратор відкриває вкладку **Інтеграції** компанії, потім **API**, і натискає **Новий ключ**. Назвіть його за платформою, яка його використовуватиме, виберіть строк дії й позначте лише те, що йому потрібно: ключ дашборда лише читає, ключ кар'єрного сайту ще й запрошує. Права можна згодом відкликати, але не додати. Ключ показується один раз — збережіть його в надійному місці.
2. Ваша платформа надсилає запити з цим ключем: отримує список співбесід компанії, список кандидатів або дані окремого кандидата з оцінкою, інформацією про те, чи пройшов він, і позначками можливого списування, а також запрошує кандидата.
3. Додайте **вебхук**: адресу на вашій платформі, на яку prepza надсилає підписаний запит, коли кандидат починає чи завершує, коли запрошення до нього не дійшло, коли термін запрошення минув або кандидата видалено, а також коли співбесіда готова, — тож не доведеться постійно перепитувати. Сторінка API може надіслати на нього тестову подію й показує його журнал доставки.

До кожного кандидата додається посилання на його повні результати в prepza, а доки він не завершив, — його особисте посилання-запрошення, щоб ваша платформа за бажання могла надіслати його у власному листі. Якщо ваша платформа вже знає, хто кандидат, запрошуйте його без входу: prepza не надсилає жодних листів, а кандидат проходить співбесіду за посиланням, не входячи в prepza, тож надсилайте посилання лише йому. Запрошення також може повернути кандидата на ваш сайт кнопкою на сторінці завершення і задати світлу чи темну тему в кольорах вашої компанії. Завдяки SDK prepza ваша власна сторінка може показувати саму співбесіду. Для повернення кандидатів і показу співбесіди на вашому сайті потрібна підтверджена компанія, і працює це лише на домені її вебсайту.

Правило те саме, що й усюди: оцінка допомагає людині ухвалити рішення, тому не відмовляйте кандидатам автоматично на її підставі.

## Що й коли використовувати

Почніть із того, хто виконує роботу і як часто.

| Ваша ситуація | Що використовувати |
| --- | --- |
| Ви в prepza і хочете швидко отримати відповідь: хто пройшов, хто не почав, скільки лишилося кредитів | Міра, вбудована асистентка |
| Ви хочете налаштувати щось кількома словами: співбесіду за описом вакансії, прохідний бал, додатковий час | Міра, вбудована асистентка |
| Ви й так увесь день працюєте в Claude чи ChatGPT і хочете, щоб prepza була там само | MCP |
| Для завдання потрібна prepza і щось іще: ваші документи, чернетки листів, інший підключений інструмент | MCP |
| Рекрутер у дорозі хоче перевірити воронку з ШІ-застосунку на телефоні | MCP |
| Ваш кар'єрний сайт чи HR-система мають самі запрошувати кандидатів, без нічиїх натискань | API |
| Результати мають потрапляти у вашу базу даних чи дашборд, щойно кандидати завершують | API з вебхуком |
| Ваша ATS — одна з тих, до яких підключається prepza (Workable, Greenhouse, Teamtailor, Recruitee, Breezy HR) | Нічого з цього: підключіть ATS на вкладці «Інтеграції». Див. [Як підключити тести навичок до ATS](/guides/ats-integration-skills-tests) |

Просте правило:

- **Людина питає й перевіряє кожну зміну:** Міра в prepza або MCP, якщо ця людина живе в Claude чи ChatGPT.
- **Програма діє сама, щоразу однаково:** API.
- **Для початку:** спробуйте Міру, вбудовану асистентку. Вона не потребує налаштування, а досвід стане в пригоді й у MCP.

Їх можна використовувати разом. Команда може надсилати запрошення зі своєї HR-системи через API, а рекрутери — питати про результати Міру чи свій ШІ-чат.

## Як отримувати хороші результати

- **Називайте речі конкретно.** «Співбесіда Senior Backend» працює краще, ніж «та співбесіда».
- **Просіть по одному кроку,** коли це важливо. Перевірте результат, потім просіть про наступний.
- **Прочитайте запит на схвалення, перш ніж дозволити.** У ньому точно вказано, що буде виконано.
- **Питайте, звідки взялася цифра.** Хороший агент може показати кандидатів або сторінку, на яких вона ґрунтується.
- **Залишайте рішення людям.** Використовуйте агента, щоб знайти, відсортувати й підготувати; вирішуйте самі.

## Ціни

Міра, підключення через MCP і API безкоштовні. Ви платите лише за кандидатів, як і завжди: за кожного кандидата, який відповів хоча б на одне питання, без підписки. Див. [ціни](/pricing).
